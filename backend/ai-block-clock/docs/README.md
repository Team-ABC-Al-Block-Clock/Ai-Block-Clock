### 표기

[`example.png`](diagrams/example.png) 를 따른다.

- **바깥 상자 = 묶음**, 안의 둥근 상자 = 모델
- 그리는 대상 묶음은 파란 테두리, 참조만 하는 이웃 묶음은 회색 테두리
- 화살표는 참조 방향. 되돌아오는 화살표가 보이면 그림이 아니라 코드를 의심한다
- 애그리거트와 주요 모델까지만 그린다. 값 객체는 표로 적는다

Mermaid 로 적는다. `ARCHITECTURE.md` 1.1 이 이미 이 방식이고, 텍스트라 diff 가 남아
코드를 고친 사람이 그림도 같은 커밋에서 고칠 수 있다. Mermaid 로 어려운 그림만 이미지를 두고
그린 원본(draw.io 등)을 함께 커밋한다.

### 파일명

**작업 단위로 나눈다.** 한 파일에 전부 담지 않는다.

```
diagrams/graph.md       노드 · 연결선 · 그래프
diagrams/workflow.md    워크플로우 애그리거트
diagrams/agent.md       에이전트 · 버전 애그리거트
```

패키지 이름을 그대로 쓴다. 여러 묶음에 걸치는 흐름은 `capsulation-flow.md` 처럼
동작 이름으로 따로 만든다.

### 지켜야 할 것

- **코드와 어긋나면 코드가 맞다.** 그림은 코드를 따라간다.
- 구조를 바꾸는 MR 은 관련 그림도 같이 고친다. 못 고치면 MR 본문에 어느 그림이 낡았는지 적는다.
- 그림에 쓰는 말은 저장소 루트의 `GLOSSARY.md` 를 따른다. 새 말이 필요하면 거기부터 고친다.
- 계층·모듈을 그릴 때는 `ARCHITECTURE.md` 와 `MODULES.md` 가 원본이다. 그림이 그 문서와 달라지면 그림이 틀린 것이다.
