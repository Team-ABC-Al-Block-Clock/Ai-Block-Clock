## 1. `ref_files` 의 값이 어떤 모양인가요

노드 필드에 `ref_files` 가 있다고만 적혀 있고 값의 모양이 없습니다 (§5.2). 지금은 **올린 파일 이름의
배열**로 보내고 있습니다.

```jsonc
{ "id": "n1", "type": "llm", "prompt": "...",
  "ref_files": ["채점 기준표.pdf", "양식.md"] }
```

| | |
| --- | --- |
| **1-1** | 이름 배열이 맞나요, 아니면 객체 배열인가요 |
| **1-2** | 파트 이름의 `<n>` 이 **0 부터**인가요 1 부터인가요. 지금은 `ref_file_n1_0` 으로 보냅니다 |
| **1-3** | 파일 이름은 폼 헤더가 US-ASCII 라 한글이 깨집니다. 그래서 파트에는 `{자료 ID}.pdf` 처럼 ASCII 이름으로 싣고, **사람이 읽을 이름은 `ref_files` 에만** 담았습니다. 이렇게 보내도 되나요 |

**틀려도 한 줄만 고치면 됩니다.** 다만 맞춰 두지 않으면 실행에서 `REF_FILE_REJECTED` 가 나고 그것이
공급자 책임으로 집계되어서 미리 여쭙습니다.

## 2. 자연어 한 줄로 단계 초안을 만들어 줄 수 있을까요

에이전트를 만들려면 공급자가 **단계를 몇 개로 나눌지 판단하고, 각 단계 프롬프트를 쓰고,
앞 단계 출력이 뒤에 어떤 모양으로 들어갈지까지** 맞춰야 합니다.

"학원 성적을 분석해서 학부모에게 보낼 리포트를 만들고 싶어" 한 줄을 받아
**단계 초안(이름 + 프롬프트)을 뽑아주는 기능**이 있으면, 공급자 진입 장벽이 크게 낮아집니다.

결과물은 저희가 노드 여러 개로 저장하면 되므로 **구조는 바뀌지 않습니다.**
추천 서비스 쪽에 붙이는 게 자연스러워 보이는데, 어떻게 보시는지 궁금합니다.

**급하지 않습니다.** 다만 없으면 마켓에 공급자가 물건을 올리기 어려울 것 같아 미리 여쭙습니다.

## 3. 입출력 노드를 캔버스에 두려 합니다

가이드 §5.2 는 입출력 노드(H2A · A2A2H)를 **캔버스의 노드로 그리지 않는다**고 적습니다. 그런데 저희
요구사항 정의서(WRK-008 · WRK-009)는 입출력 노드를 MVP 에 두고, 사용자가 **무엇을 넣고 무엇을 받을지**
직접 정하게 해야 합니다.

그래서 **화면과 저장소에서는 노드로 두되, 실행 요청으로 보낼 때 번역**하려 합니다. 번역하는 길이 둘로
보이는데 어느 쪽이 Runtime 이 기대하는 모양인지 알려 주시면 좋겠습니다.

| | 어떻게 |
| --- | --- |
| **갈래 A** | 형식을 바꾸는 `llm` 노드를 앞뒤에 하나씩 끼운다. `output_schema_id` 로 형식을 걸어 Runtime 의 출력 강제 · 교정을 그대로 쓴다 |
| **갈래 B** | 첫 작업 노드에 `input_schema_id` 를, 마지막 작업 노드에 `output_schema_id` 를 **저희가 찍어서** 보낸다 |

| | |
| --- | --- |
| **3-1** | 둘 중 어느 쪽이 맞나요. 혹시 Runtime 이 따로 생각해 둔 세 번째 방식이 있나요 |
| **3-2** | 갈래 A 로 가면 그 두 노드는 **판매자가 없는 플랫폼 노드**입니다. `owner_id` 를 비워 보내려 하는데, 그 노드가 실패하면 `fault` 가 `supplier` 로 오는 것으로 읽었습니다. **플랫폼이 끼운 노드임을 구분할 방법이 있나요.** 없으면 저희가 `node_id` 로 가려내면 되는지 확인 부탁드립니다 |
| **3-3** | 같은 노드는 `unit_price` 도 없습니다. 가이드가 "`0` 으로 채워 보내지 말라" 고 해서 비우려 하는데, 그러면 `validate` 견적에서 `unpriced_nodes` 에 잡혀 화면에 "단가 미정" 이 뜹니다. **판매자 없는 노드를 견적에서 빼는 방법**이 있을까요 |
| **3-4** | 갈래 B 는 노드마다 `input_schema_id` · `output_schema_id` 를 저장해야 성립합니다. 저희는 아직 그 칸이 없습니다. **노드 단위 스키마를 언제까지 붙여야 하는지** 일정 감각을 알려 주시면 순서를 그에 맞추겠습니다 |

**갈래 A 로 기운 이유**는 마지막 작업 노드가 **남이 만든 노드**일 수 있어서입니다. 저희가 형식을
덮어쓰면 그 노드는 의도하지 않은 형식을 내야 하고, 실패하면 `SCHEMA_VALIDATION_FAILED` · `supplier`
책임으로 **그 판매자의 성공률이 깎입니다.** 저희가 끼운 형식 때문에 남의 등급이 내려가는 구조를 둘 수
없어서 노드를 따로 끼우는 쪽을 보고 있습니다. 이 읽기가 맞는지도 함께 봐 주시면 좋겠습니다.

## 4. 결과 형식을 요청에 실어 보내려 합니다

사용자가 에이전트를 만들 때 **결과를 PDF · 마크다운 · 엑셀 · CSV 중 무엇으로 받을지** 고르게 하려
합니다. 그 값은 워크플로우에 저장되고, 실행 요청에 함께 나가야 한다고 보고 있습니다.

**렌더가 실행의 일부라서입니다.** 완료 응답의 `result` 에 `pdf_url` 이 이미 들어 있으니 실행이 끝나는
시점에 PDF 가 만들어져 있고, 그러려면 무엇으로 렌더할지가 요청에 실려 있어야 합니다. 지금은 PDF
하나뿐이라 실을 것이 없었던 것으로 읽었습니다.

```jsonc
// 저희가 보내려는 모양 — 칸 이름은 정해 주시는 대로 맞추겠습니다
"output": { "schema_id": "common.table@1", "format": "xlsx", "template_id": null }
```

| | |
| --- | --- |
| **4-1** | **마크다운 · 엑셀 · CSV 를 지원하실 수 있나요.** 된다면 요청의 어느 칸에 실어야 하는지 이름을 정해 주세요. 완료 응답에서는 `result.type` 이 그 값이 되는지, `md_url` · `xlsx_url` 처럼 칸이 느는지도 함께 알려 주시면 받는 쪽을 맞추겠습니다 |
| **4-2** | 엑셀과 CSV 는 `common.table@1` 처럼 표 형식일 때만 말이 됩니다. **결과 스키마와 형식의 조합에 제약이 있나요.** 대응표를 주시면 저장할 때 거르고 화면에서도 감추겠습니다. **답이 오기 전에는 조합을 막지 않겠습니다** — 짐작으로 막으면 멀쩡한 저장을 거부하게 되어서입니다 |
| **4-3** | `output.template_id` 로 **고를 수 있는 값의 목록을 어디서 받나요.** 카탈로그처럼 주는 엔드포인트가 보이지 않아, 지금은 비워 보내 기본 템플릿으로 렌더할 생각입니다 |

**급한 것은 4-1 의 가부입니다.** 안 된다고 하시면 저희가 렌더를 맡아야 해서 일정과 의존(엑셀 라이브러리)을
다시 잡아야 합니다. 형식이 실제로 붙는 시점은 뒤여도 괜찮습니다 — **저장 칸과 화면은 먼저 열어 두고
보낼 자리만 비워 두겠습니다.**

## 저희 쪽 결정 중 알아두시면 좋을 것

### 용어 — "캡슐화"

저희는 코드에서 이 말을 걷어내고 **버전 생성 · 확정 · 공개** 셋으로 나눴습니다.
"내부를 숨긴다" 는 부분이 서비스 설명이지 동작이 아니어서입니다.

연동 가이드에는 "캡슐화" 가 그대로 쓰여 있는데, 문서를 고쳐달라는 뜻은 아닙니다.
**요구사항 정의서 용어를 정리할 때 같이 보면 좋겠다**는 정도입니다.

### 오류 응답 형식

AI Runtime 은 `{"detail": {code, message, errors}}`, 저희 API 는 다른 봉투를 씁니다.
**저희가 번역합니다.** 알려주실 것은 없고, 오류 코드가 늘면 공유만 부탁드립니다.
