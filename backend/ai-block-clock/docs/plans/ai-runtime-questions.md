## 1. 참고 자료 파일명이 LLM 에 보입니다

참고 자료는 file-store 키(`nodes/{노드 ID}/{자료 ID}.pdf`) 그대로 SubmitRun 의 `ref_files` 경로로 보내고(10-16, 그 전에는
같은 ASCII 이름의 폼 파트), **사람이 읽을 이름은 노드 정의의 `ref_files` 에만** 담았습니다. 그런데 엔진은 **파일명**을
LLM 에 보이는 첨부 이름으로 씁니다. 지금은 LLM 이 UUID 를 봅니다.

| | |
| --- | --- |
| **1-3** | 첨부 이름으로 노드 정의 `ref_files` 의 이름을 같은 순서로 쓰실 수 있나요 |

## 2. 자연어 한 줄로 단계 초안을 만들어 줄 수 있을까요

에이전트를 만들려면 공급자가 **단계를 몇 개로 나눌지 판단하고, 각 단계 프롬프트를 쓰고,
앞 단계 출력이 뒤에 어떤 모양으로 들어갈지까지** 맞춰야 합니다.

"학원 성적을 분석해서 학부모에게 보낼 리포트를 만들고 싶어" 한 줄을 받아
**단계 초안(이름 + 프롬프트)을 뽑아주는 기능**이 있으면, 공급자 진입 장벽이 크게 낮아집니다.

결과물은 저희가 노드 여러 개로 저장하면 되므로 **구조는 바뀌지 않습니다.**
추천 서비스 쪽에 붙이는 게 자연스러워 보이는데, 어떻게 보시는지 궁금합니다.

**급하지 않습니다.** 다만 없으면 마켓에 공급자가 물건을 올리기 어려울 것 같아 미리 여쭙습니다.

## 4. 결과 형식을 요청에 실어 보내려 합니다

사용자가 에이전트를 만들 때 **결과를 PDF · 마크다운 · 엑셀 · CSV 중 무엇으로 받을지** 고르게 하려
합니다. 그 값은 워크플로우에 저장되고, 실행 요청에 함께 나가야 한다고 보고 있습니다.

**렌더가 실행의 일부라서입니다.** 완료 응답의 `result` 에 `pdf_url` 이 이미 들어 있으니 실행이 끝나는
시점에 PDF 가 만들어져 있고, 그러려면 무엇으로 렌더할지가 요청에 실려 있어야 합니다. 지금은 PDF
하나뿐이라 실을 것이 없었던 것으로 읽었습니다.

```jsonc
// 저희가 보내려는 모양 — 칸 이름은 정해 주시는 대로 맞추겠습니다
"output": { "schema_id": "common.table@1", "format": "xlsx", "template_id": null }
```

| | |
| --- | --- |
| **4-1** | **마크다운 · 엑셀 · CSV 를 지원하실 수 있나요.** 된다면 요청의 어느 칸에 실어야 하는지 이름을 정해 주세요. 완료 응답에서는 `result.type` 이 그 값이 되는지, `md_url` · `xlsx_url` 처럼 칸이 느는지도 함께 알려 주시면 받는 쪽을 맞추겠습니다 |
| **4-2** | 엑셀과 CSV 는 `common.table@1` 처럼 표 형식일 때만 말이 됩니다. **결과 스키마와 형식의 조합에 제약이 있나요.** 대응표를 주시면 저장할 때 거르고 화면에서도 감추겠습니다. **답이 오기 전에는 조합을 막지 않겠습니다** — 짐작으로 막으면 멀쩡한 저장을 거부하게 되어서입니다 |
| **4-3** | `output.template_id` 로 **고를 수 있는 값의 목록을 어디서 받나요.** 카탈로그처럼 주는 엔드포인트가 보이지 않아, 지금은 비워 보내 기본 템플릿으로 렌더할 생각입니다 |

**급한 것은 4-1 의 가부입니다.** 안 된다고 하시면 저희가 렌더를 맡아야 해서 일정과 의존(엑셀 라이브러리)을
다시 잡아야 합니다. 형식이 실제로 붙는 시점은 뒤여도 괜찮습니다 — **저장 칸과 화면은 먼저 열어 두고
보낼 자리만 비워 두겠습니다.**

## 저희 쪽 결정 중 알아두시면 좋을 것

### 용어 — "캡슐화"

저희는 코드에서 이 말을 걷어내고 **버전 생성 · 확정 · 공개** 셋으로 나눴습니다.
"내부를 숨긴다" 는 부분이 서비스 설명이지 동작이 아니어서입니다.

연동 가이드에는 "캡슐화" 가 그대로 쓰여 있는데, 문서를 고쳐달라는 뜻은 아닙니다.
**요구사항 정의서 용어를 정리할 때 같이 보면 좋겠다**는 정도입니다.

### 오류 응답 형식

AI Runtime 은 `{"detail": {code, message, errors}}`, 저희 API 는 다른 봉투를 씁니다.
**저희가 번역합니다.** 알려주실 것은 없고, 오류 코드가 늘면 공유만 부탁드립니다.
