## 2. 노드별 출력 형식 — FE 2

### 2.1 WRK-005 는 설 자리가 없어졌다

> 어떤 노드 사이에도 선을 그을 수 있다. 형식 호환 검사는 없다. — 계약 §5.3

| 09-22 | v2.0 |
| --- | --- |
| 앞 `output_schema_id` = 뒤 `input_schema_id` 일 때만 잇는다 | **어떤 노드든 잇는다.** 뒤 노드가 앞 결과 전체를 받는다 |
| `input_schema_id` 로 입력을 검증한다 | **입력 형식이 없다.** 진입 노드에만 `input.sample`(폼 견본, 선택) |
| `output_schema_id` 가 카탈로그 11종 중 하나로 필수 | `output: {kind: "text"}` 또는 `{kind: "json", sample: "<견본 id>"}` |

364 는 WRK-006 까지로 줄이고 WRK-005 는 기획에 올린다.

### 2.2 그래도 해야 하는 것

**노드마다 `output` 은 v2.0 의 필수 칸이다.** 지금은 `RuntimeWorkflow` 가 위치로 정한 상수(`common.text@1` ·
`common.document@1`)를 옛 필드 `output_schema_id` 로 보내고, 엔진이 이것을 한 버전 동안만 별칭으로 읽어 준다.
**별칭이 사라지면 모든 실행이 `MISSING_OUTPUT` 400 이다.**

09-19 계약부터 필수였는데, 실행을 붙일 때(09-23) 저장하지 않고 상수로 채웠고 차이를 문서에만 적어 두었다.

| 출력 형식이 쓰이는 곳 | |
| --- | --- |
| 실행 요청의 노드 `output` (필수) | BE 가 싣는다 |
| 분기 조건 — `left` 노드는 `json` 이어야 하고 필드가 견본에 있어야 한다 | 엔진 `validate` 가 검사, FE 가 필드 드롭다운을 그린다. **이것이 없어 분기를 실행할 수 없다** |
| 마켓 카드 — "입력: 자유 / 출력: 글" | FE 가 그린다 |

### 2.3 정한 것

| | 결정 | 근거 |
| --- | --- | --- |
| 형식을 만드는 방식 | **AI 견본 11종에서 고른다** | 판매자가 필드를 직접 정의하는 것은 엔진의 "다음 버전"이다. 엔진이 받지 못하는 칸을 BE 가 미리 받지 않는다 |
| 누가 고르나 | **공급자가 노드를 만들 때.** 기본은 `text` | 에이전트로 굳힐 때 함께 고정되고, 사서 쓰는 사람은 바꾸지 못한다 |
| 칸 모양 | 계약과 같게 `output: { kind, sample }` | FE 가 계약 모양을 그대로 쓴다 |

**한계:** 견본 11종 중 분기에 쓸 스칼라 필드가 있는 것은 브랜드 시연용 `biz.*` 뿐이다. 시연 밖 도메인(성적 · 등급 등)은
맞는 견본이 없어 분기를 쓰기 어렵다. 엔진이 판매자 정의 필드를 열면 풀린다.

### 2.4 정할 것

| | 선택지 |
| --- | --- |
| 끝 노드 `resultShape` | v2.0 의 최종 결과는 마지막 노드가 제 `output` 으로 낸 것이라 역할이 겹친다. 걷어낼지 둘지 |
| 견본 목록 | `GET /v1/schemas` 를 중계할지(계약 권장, AI 가 늘려도 BE 를 안 고친다), BE 에 복사해 둘지 |

### 2.5 할 일

| | BE | FE |
| --- | --- | --- |
| 저장 | `node_definition` · `agent_version_node` 에 `output_kind` · `output_sample`. 기존 행은 `text` | 노드 편집에 "출력 형식: 글 / 견본" |
| API | 노드 저장 · `LLM` 배치 본문에 `output`(선택). 노드 상세 · 워크플로우 상세 · 배치 가능 목록에 실음 | 분기 조건에 필드 드롭다운. 글 출력 노드는 기준 목록에서 뺀다 |
| 견본 | 2.4 에 따라 중계 또는 복사 | 견본의 한국어 이름으로 선택지 |
| 실행 | 상수 대신 저장값을 `output {kind, sample}` 로. 옛 필드와 최상위 `output.schema_id` 를 뺀다 | — |

마이그레이션이 들어가므로 Flyway 번호는 열린 MR 뒤로 민다.

| | 지금 | v2.0 | 상태 |
| --- | --- | --- | --- |
| 원가 | `ExecutionUsage` 가 `nodes[].cost_abc` 만 더한다 | `cost_abc` 를 보내지 않고 `cost_usd` 만 준다. 그대로면 사용액 0 → 성공한 실행도 전액 환불 | **정산팀 몫** |

| `validate` | 부르지 않는다 | 금액 없이 `worst_case_nodes` 와 분기 검사 | 분기 실행을 열 때 |
| `RunStatus` 죽은 칸 | `charged_abc` · `refund_abc` · `Result.schema_id` | 오지 않는다 | 정산팀과 함께 걷어낸다 |
| 참고 자료 파트 파일명 | `{자료 ID}.확장자` | 엔진이 파트 파일명을 LLM 에 보이는 첨부 이름으로 쓴다 | LLM 이 UUID 를 본다. 원래 이름을 실을지 정한다 |
| 서비스 토큰 | 환경변수 `AI_SERVICE_TOKEN`. `compose.prod.yaml` 에 주입이 없다 | 헤더 `X-ABC-Service-Token`, 값은 GitLab 변수 `ABC_SERVICE_TOKEN` | 운영 설정 확인 |

### 4.1 모델 — 알고 둔 한계

엔진(`runner.py:270`)은 실행 한 건에 LLM 을 하나 만들고 **최상위 `model` 만 읽는다.** 노드의 `model` 은 읽지 않고,
Gemini(GMS)만 부른다. 우리는 노드마다 모델을 저장하므로 선택지가 둘이 된 지금(Flash · Pro), **한 워크플로우에 둘이
섞이면 첫 단계의 모델로 전부 돈다.** 판매자가 고른 모델로 돌지 않고 오류도 나지 않는다.

엔진이 노드별 `model` 을 받아야 풀린다. 노드별 모델 칸은 그때 그대로 실으려고 둔다. 원가는 모델과 무관하게 3 ABC 다.
