# 끝난 설계 — 에이전트 파이프라인

[`../agent-pipeline.md`](../agent-pipeline.md) 에서 **구현이 끝나** 걷어낸 장이다. 지금 코드가
왜 그 모양인지 되짚을 때만 본다. **현재 규칙의 원본이 아니다** — 규칙은 `docs/RULE.md`,
구조는 `docs/ARCHITECTURE.md` 가 원본이다.

### 4.1 프로필

| FE 가 보내는 것 | 우리 |
| --- | --- |
| `name` · `summary` · `description` · `usageExample` · `onboardingMessage` | `AgentProfile` 에 그대로 |
| — | `thumbnailUrl` 은 남겼다. 아이콘 업로드가 붙을 자리다 |

`category` · `tags` 는 **걷어냈다.** 마켓 목록에도 상세에도 나오지 않고, FE 가 보내지도 않는다.

> 카테고리·등급·공개 범위 필터는 명세에 없고, 화면에 표시할 자리가 없다 — `agents.ts`

### 6.1 지금 표현되지 않는 것

`GraphNode` 가 답하는 것은 셋뿐이다 — 어느 자리인가, 어떤 종류인가, 무엇을 가리키는가.
전부 **배치 정보**다. "이것이 실행되면 결과를 내는 한 덩어리다" 는 어디에도 없다.

그래서 아래 셋을 물을 데가 없다.

| 물음 | 지금 |
| --- | --- |
| 이 자리에 놓인 것의 **값이 얼마인가** | 값은 `AgentVersion` 에만 있다 |
| 실행하면 **프롬프트 몇 개로 펼쳐지는가** | 펼치기라는 개념이 없다 |
| **누구 것인가** | `AgentPlacement` 로 에이전트만 골라낸다. 노드는 못 본다 |

### 6.2 합성 구조다

한 자리에 놓이는 것은 둘 중 하나다.

- **잎** — 노드. 프롬프트 하나, LLM 한 번. 더 쪼개지지 않는다.
- **가지** — 에이전트 버전. 안에 그래프가 있고 거기 또 잎과 가지가 있다.

고리는 이미 코드에 있다.

```
그래프 ──담는다──> AgentNode ──(식별자, 조회 필요)──> AgentVersion ──담는다──> 그래프
```

`AgentNode` 가 식별자만 들어 **한 칸이 끊겨 있다.** 끊어 둔 것은 맞다. 객체를 직접 물면 워크플로우
하나 읽는데 에이전트가 통째로 딸려 온다. 애그리거트를 넘는 참조는 식별자여야 한다.

문제는 **그 끊긴 고리를 이어 걷는 타입이 없다**는 것이다. 구조는 있는데 그것을 다루는 물건이 없다.

### 6.3 없으면 같은 분기가 네 군데에서 반복된다

| 어디 | 무엇을 |
| --- | --- |
| 저장할 때 | 펼친 경로 길이가 상한을 넘는가 |
| 팔 때 | 놓인 것이 전부 내 것인가 |
| 선차감할 때 | 놓인 것들의 값 합이 얼마인가 |
| 주문서 만들 때 | 놓인 것을 프롬프트 목록으로 편다 |

네 군데 전부 `sourceType` 을 보고 갈라지게 된다. **한 곳만 고치고 다른 데를 빠뜨리는 것이 시간 문제다.**
