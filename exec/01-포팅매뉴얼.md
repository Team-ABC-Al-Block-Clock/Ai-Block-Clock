## 2. 로컬 빌드 · 실행

### 2.1 백엔드

```bash
cd backend/ai-block-clock
cp .env.example .env                 # 로컬 기본값이 이미 채워져 있다
docker compose up -d --build         # MySQL + RabbitMQ + 백엔드 (dev 프로파일, :8080)
```

RabbitMQ 관리 UI 는 `http://localhost:15672`(로컬 계정 `guest` / `guest`)다.

Docker 없이 띄우면 기본 프로파일 `local` 로 **인메모리 H2** 에 붙는다.

```bash
./gradlew clean build                # 컴파일 + 단위 테스트 → core/core-api/build/libs/*.jar
./gradlew test                       # 단위 테스트 (@Tag("integration"), @Tag("container") 제외)
./gradlew integrationTest            # @Tag("integration")
./gradlew containerTest              # @Tag("container") — 실제 MySQL · RabbitMQ 컨테이너 사용
```

API 문서: `http://localhost:8080/api/swagger-ui.html`

### 2.2 프론트엔드

```bash
cd frontend
cp .env.example .env.local           # 실제 백엔드에 붙이려면 VITE_USE_MOCK=false
npm ci
npm run dev                          # http://localhost:5173, /api 는 :8080 으로 프록시
npm run build                        # tsc -b && vite build → dist/
```

`VITE_USE_MOCK` 이 비어 있거나 `true` 면 MSW 목 응답으로 뜬다(백엔드 없이 개발 가능).

### 2.3 AI 실행 엔진

```bash
cd ai/spike/linear-mvp
uv sync
cp .env.example .env                 # LLM_API_KEY (SSAFY GMS 팀 키) 를 채운다
uv run uvicorn src.api:app --host 0.0.0.0 --port 8000
```

실행 요청은 HTTP 가 아니라 RabbitMQ 로 온다. 백엔드 compose 를 먼저 띄우면 `localhost:5672`(`guest`)에 붙는다.
브로커 없이 조회 API 만 쓰려면 `BROKER_ENABLED=false` 로 띄운다. 파일 경로 기준은 `FILE_STORE_ROOT` ·
`RESULTS_ROOT`(기본은 프로젝트 아래 `file-store/` · `results/`)이고, 백엔드와 같은 폴더를 가리켜야 파일이 오간다.

### 2.4 AI 추천 엔진

```bash
cd ai/recommend
pip install -r requirements.txt httpx      # httpx 는 seed_index.py 가 쓴다
uvicorn app.main:app --reload --port 8100  # 터미널 1
python seed_index.py                       # 터미널 2 — 서버가 뜬 뒤 시드 에이전트 주입
```

로컬에는 파인튜닝 가중치가 없어 사전학습 모델 `jhgan/ko-sroberta-multitask` 로 뜬다.

## 3. 환경 변수

### 3.1 프론트엔드 (빌드 타임)

Vite 는 `VITE_*` 를 **빌드 시점에 번들에 박아 넣는다.** 런타임 주입이 안 되므로 값이 바뀌면
다시 빌드해야 한다. **키 · 토큰류는 절대 `VITE_` 로 넣지 않는다** — 번들에 그대로 노출된다.

| 변수 | 운영 값 | 설명 |
| --- | --- | --- |
| `VITE_APP_NAME` | `ABC AI Block Clock` | 화면 표기용 |
| `VITE_API_BASE_URL` | `/api` | 같은 오리진이라 CORS 설정이 필요 없다 |
| `VITE_API_PROXY_TARGET` | (배포에는 불필요) | 로컬 `vite.config.ts` 프록시 대상 |
| `VITE_USE_MOCK` | `false` | 비우거나 `true` 면 MSW 목으로 뜬다. **운영 빌드에서는 반드시 false** |

비밀값이 아니므로 `.env.production` 을 저장소에 커밋해 관리한다.

### 3.2 백엔드 (런타임 주입)

GitLab CI/CD Variables 로 관리하고 저장소에 두지 않는다. Docker Compose 가 프로세스
환경변수에서 `${...}` 를 보간하므로 CI 잡 환경에 들어오면 그대로 쓰인다.

> **운영 서버에 `/etc/j15a403/backend.env` 는 없다** (2026-09-28 확인). 값은 전부 GitLab
> CI/CD Variables 에서 온다. 손으로 `docker compose` 를 돌려야 한다면 그 셸에 같은 변수를
> `export` 하거나 `--env-file` 로 쓸 파일을 직접 만들어야 한다.

**필수 (없으면 기동 실패 또는 배포 잡 실패)**

| 변수 | 운영 값 | 비고 |
| --- | --- | --- |
| `MYSQL_DATABASE` | **`ai-block-clock`** (하이픈) | Protected. compose 기본값 `ai_block_clock` 과 다르다 |
| `MYSQL_USER` | **`admin`** | Protected. compose 기본값 `ai_block_clock` 과 다르다 |
| `MYSQL_PASSWORD` | 강한 비밀번호 | Protected · **Masked** |
| `MYSQL_ROOT_PASSWORD` | 강한 비밀번호 | Protected · **Masked** |
| `DB_URL` · `DB_USERNAME` · `DB_PASSWORD` | compose 가 위 값으로 조립 | `prod` 프로파일은 **기본값이 없다** — 누락 시 기동 실패 |

> ⚠️ **DB 이름과 계정이 compose 기본값과 다르다.** 운영은 `ai-block-clock` / `admin` 이고,
> `compose.yaml` 의 기본값은 `ai_block_clock` / `ai_block_clock` 이다. GitLab 변수를 비운 채
> 배포하면 **빈 DB 가 새로 만들어져** 기존 데이터가 안 보인다.

**실행 메시지 브로커 (RabbitMQ)**

| 변수 | 운영 값 | 비고 |
| --- | --- | --- |
| `RABBITMQ_USERNAME` | 브로커 계정 이름 | **Protected.** 필수 — 비면 `backend:deploy` · `ai:deploy` 가 멈춘다. 백엔드 · 런타임 · 브로커가 같은 값을 쓴다 |
| `RABBITMQ_PASSWORD` | 강한 비밀번호 | **Protected · Masked.** 필수. 같은 값을 셋이 쓴다 |
| `RABBITMQ_VHOST` | `/` | 기본값 그대로 |
| `RABBITMQ_HOST` · `RABBITMQ_PORT` | `ai-block-clock-rabbitmq` · `5672` | compose 가 지정한다 |
| `RESULTS_ROOT` | `/var/lib/ai-block-clock/results` | compose 가 지정한다. 런타임이 결과물을 쓰는 `results` 볼륨의 마운트 위치 |

> ⚠️ **브로커 계정은 처음 뜰 때만 만들어진다.** `rabbitmq-data` 볼륨이 비어 있을 때
> `RABBITMQ_USERNAME` · `RABBITMQ_PASSWORD` 로 계정이 생기고, 그 뒤에 변수만 바꾸면 반영되지 않는다.
> 비밀번호를 바꿀 때는 `docker exec ai-block-clock-rabbitmq rabbitmqctl change_password <계정> <새 비밀번호>`
> 로 바꾸고 GitLab 변수도 같이 바꾼다.

**인증 · 세션**

| 변수 | 운영 값 | 기본값 |
| --- | --- | --- |
| `SPRING_PROFILES_ACTIVE` | `prod` | compose.prod.yaml 이 지정 |
| `WALLET_AUTH_DOMAIN` | `j15a403.p.ssafy.io` | `localhost:5173` |
| `WALLET_AUTH_URI` | `https://j15a403.p.ssafy.io/` | `http://localhost:5173/` |
| `WALLET_AUTH_CHAIN_ID` | `31221` | `31221` |
| `WALLET_AUTH_MESSAGE_TTL` | `5m` | `5m` |
| `AUTH_COOKIE_SECURE` | `true` | 로컬 `false` |
| `AUTH_SESSION_TIMEOUT` | `2h` | `2h` |
| `ADMIN_WALLET_ADDRESSES` | 관리자 지갑 주소(쉼표 구분) | 빈 값 — **비우면 아무도 심사할 수 없다** |
| `API_DOCS_ENABLED` | `true` | 관리자가 Swagger 로 심사하므로 켜 둔다 |

**AI 연동**

| 변수 | 운영 값 | 비고 |
| --- | --- | --- |
| `AI_RUNTIME_BASE_URL` | `http://ai-block-clock-ai-runtime:8000` | 같은 도커 네트워크, 컨테이너 이름 |

**체인 (개인키 — 서버에만)**

| 변수 | 용도 | 운영 상태 (2026-09-28) | 없으면 |
| --- | --- | --- | --- |
| `SSAFY_CHAIN_SIGNER_PRIVATE_KEY` | 보관 지갑 → 판매자 출금 지급 서명 | **설정됨** (64자) | 서명하지 않음 |
| `PAYMENT_WITHDRAWAL_PAYOUT_ENABLED` | 출금 지급 스위치 | **`true`** | 승인된 출금이 `APPROVED` 로 대기 |
| `SSAFY_AGENT_REGISTRY_SIGNER_PRIVATE_KEY` | 에이전트 등기부 기록 서명 | **설정됨** (64자) | 기록이 `PENDING` 으로 적재만 됨 |
| `AGENT_PROVENANCE_REGISTRATION_ENABLED` | 원본 증명 스위치 | **`true`** | 같음 |

> **운영은 둘 다 켜져 있다.** 승인한 출금은 실제로 체인에 나가고, 공개한 에이전트는
> 등기부에 기록된다. 시연에서 되돌릴 수 없는 동작이라는 뜻이다.
>
> 개인키는 **GitLab Masked Variable 에만** 둔다. 저장소 · 채팅 · 이슈에 붙이지 않는다.

**그 밖에 기본값이 있어 보통 건드리지 않는 것** (전체는 `core-api/src/main/resources/application.yaml`)

| 변수 | 기본값 | 의미 |
| --- | --- | --- |
| `FILE_STORE_ROOT` | `/var/lib/ai-block-clock/files` | 업로드 파일 저장 경로 (compose 볼륨 `file-store`, 런타임이 읽기 전용으로 나눠 쓴다) |
| `PAYMENT_CHARGE_CUSTODY_ADDRESS` | `0x64e7…B6B6` | 충전 입금 전용 보관 지갑 |
| `PAYMENT_CHARGE_CHAIN_ID` | `31221` | |
| `NODE_BASE_COST_DEFAULT` | `0.0135` | 측정값 없는 노드의 기본 원가(ABC) |
| `ABC_PER_USD` | `1` | 1 ABC = 1 달러 |
| `EXECUTION_POLL_PER_STEP` · `EXECUTION_POLL_GRACE` | `60s` · `60s` | 감시 기한 = 단계 수 × per-step + grace. 마지막 이벤트에서 이만큼 조용하면 엔진에 한 번 묻는다(키 이름은 폴링 시절 그대로) |
| `EXECUTION_WATCH_INTERVAL` | `10s` | 감시 기한을 점검하는 주기 |
| `EXECUTION_DISPATCH_INTERVAL` | `5s` | 아직 브로커로 넘기지 못한 실행을 다시 발행하는 주기 |
| `EXECUTION_DISPATCH_ABANDON_AFTER` | `10m` | 접수하고 이만큼 넘기지 못한 실행은 버리고 전액 환불 |
| `AI_MESSAGING_CONFIRM_TIMEOUT` | `5s` | 발행 뒤 브로커 confirm 을 기다리는 한도 |
| `AGENT_GRADE_REGRADE_CRON` | `0 0 3 * * *` | 등급 · 단가 재산정 (Asia/Seoul) |

`EXECUTION_POLL_WORKERS` · `EXECUTION_POLL_INTERVAL`(2초 폴링)과 `execution.recovery.dispatch-grace` 는 없어졌다.
남아 있어도 읽지 않는다.

### 3.3 AI (런타임 주입)

GitLab CI/CD Variables 에 넣고 compose 가 컨테이너 환경변수로 주입한다. `LLM_API_KEY` · `ABC_SERVICE_TOKEN` 은 **Masked**.

| 변수 | 대상 | 운영 값 / 기본값 | 비고 |
| --- | --- | --- | --- |
| `LLM_API_KEY` | ai-runtime | **SSAFY GMS 팀 키** | 없으면 `ai:deploy` 가 실패한다 |
| `LLM_BASE_URL` | ai-runtime | `https://gms.ssafy.io/gmsapi/generativelanguage.googleapis.com` | 비우면 Google 직접 호출 |
| `LLM_MODEL` | ai-runtime | `gemini-2.5-pro` | |
| `ABC_SERVICE_TOKEN` | ai-runtime · recommend | 백엔드 `AI_SERVICE_TOKEN` 과 같은 값 | 비면 인증 검사를 건너뛴다 |
| `RABBITMQ_USERNAME` · `RABBITMQ_PASSWORD` | ai-runtime | 백엔드와 **같은 GitLab 변수** | 비면 `ai:deploy` 가 실패한다. 로컬 기본 `guest` |
| `RABBITMQ_VHOST` | ai-runtime | `/` | 브로커 주소는 compose 가 `ai-block-clock-rabbitmq:5672` 로 지정한다 |
| `MAX_ACTIVE_RUNS` | ai-runtime | `4` | 동시에 도는 실행 수(큐 prefetch). 넘치는 실행은 큐에서 기다린다 |
| `FILE_STORE_VOLUME` · `RESULTS_VOLUME` | ai-runtime | `ai-block-clock_file-store` · `ai-block-clock_results` | 백엔드 compose 가 만든 볼륨 이름. 바꿀 일이 없다 |
| `BACKEND_NETWORK` | 둘 다 | 비우면 CI 가 `docker network ls` 에서 찾는다 | `ai-block-clock_ai-block-clock-network` |
| `AI_RUNTIME_BIND` | ai-runtime | `127.0.0.1` (CI 가 지정) | 로컬 기본 `0.0.0.0` |
| `RECOMMEND_BIND` | recommend | `127.0.0.1` | 로컬 기본 `0.0.0.0` |
| `ABC_MODEL_DIR` | recommend | `/opt/abc/models` | 로컬 `./models` |
| `ABC_INDEX_DIR` | recommend | `/opt/abc/index` | 로컬 `./index` |

### 4.2 Nginx

운영 서버에 실제로 올라가 있는 설정이다 (`/etc/nginx/sites-available/j15a403.p.ssafy.io`,
`sites-enabled` 에 심볼릭 링크). certbot 이 443 블록과 80 → 443 리다이렉트를 넣어 준 상태다.

```nginx
server {
    server_name j15a403.p.ssafy.io;

    root /var/www/j15a403/frontend;
    index index.html;

    # SPA: react-router 경로를 새로고침해도 index.html 로 보낸다
    location / {
        try_files $uri $uri/ /index.html;
    }

    # 실행 진행 상황(SSE). /api/ 보다 먼저 적어야 이쪽이 잡는다.
    location ~ ^/api/v1/runs/[^/]+/stream$ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        proxy_http_version 1.1;
        proxy_set_header Connection "";   # keep-alive 를 끊지 않는다
        proxy_buffering off;              # 켜 두면 이벤트가 모였다 한꺼번에 나간다
        proxy_cache off;
        gzip off;                         # gzip 버퍼도 이벤트를 모은다
        proxy_read_timeout 1h;            # 기본 60초면 실행 도중 끊긴다
    }

    location /api/ {
        proxy_pass http://127.0.0.1:8080;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }

    listen 443 ssl;                                # managed by Certbot
    listen [::]:443 ssl ipv6only=on;               # managed by Certbot
    ssl_certificate     /etc/letsencrypt/live/j15a403.p.ssafy.io/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/j15a403.p.ssafy.io/privkey.pem;
    include /etc/letsencrypt/options-ssl-nginx.conf;
    ssl_dhparam /etc/letsencrypt/ssl-dhparams.pem;
}

server {
    if ($host = j15a403.p.ssafy.io) {
        return 301 https://$host$request_uri;      # managed by Certbot
    }
    listen 80;
    listen [::]:80;
    server_name j15a403.p.ssafy.io;
    return 404;
}
```

**업로드 상한은 이 파일이 아니라 `/etc/nginx/nginx.conf` 의 `http` 블록에 있다.**

```nginx
http {
    client_max_body_size 11m;   # 백엔드 multipart 상한(11MB)과 맞춘다
}
```

비워 두면 nginx 기본값 1MB 에 걸려, 1MB 가 넘는 파일은 Spring 에 닿기 전에 413 으로 끊긴다.
서버 블록에 적어도 되고 http 블록에 적어도 된다 — 운영은 http 블록 한 곳에 뒀다.

```bash
sudo ln -s /etc/nginx/sites-available/j15a403.p.ssafy.io /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx

sudo apt-get install -y certbot python3-certbot-nginx
sudo certbot --nginx -d j15a403.p.ssafy.io      # 443 블록과 80 리다이렉트를 자동으로 넣는다
```

> 프론트는 `VITE_API_BASE_URL=/api` 를 쓰므로, 같은 오리진의 `/api` 를 Nginx 가 백엔드로
> 넘겨주면 **CORS 설정 없이** 동작한다.
>
> `docs/cicd.md` 의 예시에는 `/assets/` 장기 캐시와 `location = /index.html` 무캐시 블록이
> 있지만 **운영에는 들어가 있지 않다.** 없어도 동작하고(파일명에 해시가 붙는다),
> 넣으면 배포 직후 반영이 더 확실해진다.

### 4.3 추천 서비스 가중치 · 인덱스 (필수)

### 4.4 지갑 로그인 · HTTPS

로그인이 비밀번호가 아니라 **지갑 서명**이라 주소가 하나라도 어긋나면 로그인 자체가 안 된다.

- `WALLET_AUTH_DOMAIN` / `WALLET_AUTH_URI` 가 브라우저가 실제로 접속하는 주소와 같아야 한다.
  서명 메시지에 이 값이 들어가고, 백엔드가 대조한다.
- 세션 쿠키는 `Secure` 이고 `path=/api/v1` 이다. HTTPS 가 아니면 쿠키가 저장되지 않는다.
- 도메인이 바뀌면 이 두 변수를 바꾸고 백엔드를 다시 띄운다.

### 4.5 자동 배포 (GitLab CI)

| 브랜치 | 동작 |
| --- | --- |
| `feat/*`, `hotfix/*` | 변경된 쪽 build (+ 프론트는 test) |
| `develop-FE` | frontend build + test (vitest) |
| `develop-BE` | backend build(단위) + integrationTest |
| `develop-AI` | ai build + test, deploy 는 수동 |
| **`master`** | build → test → **deploy** (프론트 · 백엔드 자동, AI 는 수동 버튼) |

**변경된 폴더에 해당하는 잡만 생성된다** (`changes:` 규칙). 잡 정의는
`.gitlab/ci/{frontend,backend,ai}.gitlab-ci.yml`.

- `frontend:build` — `node:24` 컨테이너에서 `npm ci && npm run lint && npm run build`
  → `frontend/dist/` 를 artifacts 로 (1주 보관)
- `frontend:deploy` — `dist/` 를 `/var/www/j15a403/frontend` 로 rsync
- `backend:build` — `eclipse-temurin:25-jdk` 컨테이너에서 `./gradlew clean build`
  → `core/core-api/build/libs/*.jar` 를 artifacts 로
- `backend:deploy` — `docker compose -f compose.yaml -f compose.prod.yaml up -d --build`
  (MySQL · RabbitMQ · 백엔드, 볼륨 `file-store` · `results` 도 여기서 생긴다)
  → `/actuator/health` 가 `UP` 이 될 때까지 최대 120초 대기. 이 health 에는 RabbitMQ 가 들어가지 않는다 —
  브로커가 죽어도 접수는 outbox 에 쌓이므로 백엔드는 UP 이고, 브로커는 자기 컨테이너 헬스체크로 본다
- `ai:build` / `ai:test`(mock 스모크, LLM 호출 없음) / `ai:deploy`(**수동**). `ai:deploy` 는 백엔드가 만든
  `file-store` · `results` 볼륨이 없으면 멈춘다

### 4.6 수동 배포


**순서가 있다 — 백엔드 먼저, 그다음 런타임.** 백엔드를 먼저 올려야 Docker 네트워크 · RabbitMQ ·

```bash

docker volume create ai-block-clock_file-store

```

## 5. 배포 시 특이사항

| # | 내용 |
| --- | --- |
| 1 | **Docker Compose 2.24 이상.** `compose.prod.yaml` 이 `ports: !override` 를 쓴다. 미만이면 MySQL 3306 이 외부에 그대로 열린다 |
| 2 | **백엔드 Dockerfile 은 target 이 둘이다.** `local` 은 컨테이너 안에서 컴파일, `prod` 는 CI 가 테스트까지 끝낸 jar 를 그대로 넣는다. 운영은 `prod` — 컨테이너 안에서 재컴파일하지 않는다 |
| 3 | **포트는 전부 루프백 바인딩.** 백엔드 8080, MySQL 3306, ai-runtime 8000, recommend 8100, RabbitMQ 관리 UI 15672 모두 `127.0.0.1` 에만 연다. RabbitMQ 5672 는 운영에서 아예 열지 않는다(도커 네트워크로만 붙는다). 관리 UI 는 SSH 터널(`ssh -L 15672:127.0.0.1:15672`)로 본다. 외부는 Nginx 만 거친다 |
| 4 | **AI 서비스는 Nginx 설정이 필요 없다.** 브라우저가 직접 부르지 않고 백엔드만 호출한다 |
| 5 | **추천 가중치 볼륨 필수** → [§ 4.3](#43-추천-서비스-가중치--인덱스-필수) |
| 6-1 | **운영 DB 이름 · 계정이 compose 기본값과 다르다** (`ai-block-clock` / `admin` vs `ai_block_clock` / `ai_block_clock`). GitLab 변수를 같이 옮기지 않으면 빈 DB 가 새로 만들어진다 |
| 6 | **MySQL 볼륨은 최초 1회만 초기화된다.** `mysql-data` 볼륨이 이미 있으면 `MYSQL_PASSWORD` 를 바꿔도 실제 계정 비밀번호는 안 바뀐다. `ALTER USER` 하거나 볼륨을 지우고 다시 만든다 |
| 7 | **스키마는 Flyway 가 만든다.** `ddl-auto: validate` 라 마이그레이션이 실패하면 기동도 실패한다. 배포 헬스체크 실패의 가장 흔한 원인 |
| 8 | **SSE 프록시 버퍼링을 꺼야 한다.** 켜 두면 실행 진행 상황이 모였다 한꺼번에 나가고 60초에 끊긴다 |
| 9 | **`client_max_body_size 11m`.** 비우면 Nginx 기본 1MB 에 걸려 파일 업로드가 Spring 에 닿기 전에 413 으로 끊긴다 |
| 10 | **프론트 환경변수는 빌드 타임.** 값이 바뀌면 재배포가 아니라 **재빌드**다 |
| 11 | **`ai:deploy` 는 수동 잡.** master 파이프라인에서 실행 버튼을 눌러야 올라간다 |
| 12 | **Protected 변수는 보호 브랜치에서만 주입된다.** `master` 가 GitLab 에서 Protected 로 설정돼 있어야 한다. 아니면 `MYSQL_PASSWORD 가 비어 있습니다` 로 배포가 실패한다 |
| 13 | **개인키가 없으면 조용히 기능이 꺼진다.** 출금 지급은 `APPROVED` 에서, 원본 증명은 `PENDING` 에서 멈춘다. 오류가 아니라 설계된 동작이다. **현재 운영은 둘 다 켜져 있어 실제로 체인에 나간다** |
| 14 | **관리자 지갑을 비우면 심사를 할 수 없다.** `ADMIN_WALLET_ADDRESSES` 에 지갑 주소를 넣어야 `/api/v1/admin/**` 이 열린다 |
| 15 | **등급 재산정은 하루 한 번 새벽 3시(KST).** 시연 전에 한 번 돌리려면 `AGENT_GRADE_REGRADE_CRON` 을 가까운 시각으로 잠깐 바꾼다 |
| 16 | **배포 순서는 백엔드 먼저, 그다음 런타임.** RabbitMQ 와 `results` 볼륨은 백엔드 compose 가 만든다. 런타임을 먼저 올리면 `ai:deploy` 가 "Docker 볼륨 … 이 없습니다" 로 멈춘다 |
| 17 | **볼륨 이름이 고정이다.** `ai-block-clock_file-store` · `ai-block-clock_results` 를 두 compose 가 같은 이름으로 쓴다(런타임은 `external`, file-store 는 읽기 전용). `file-store` 이름은 고정 전에 compose 가 붙이던 이름과 같아 기존 업로드가 그대로 보인다. 바꾸면 빈 볼륨이 새로 생긴다 |
| 18 | **RabbitMQ 계정은 최초 1회만 만들어진다.** `rabbitmq-data` 볼륨이 이미 있으면 `RABBITMQ_PASSWORD` 를 바꿔도 브로커 계정은 그대로다(6번 MySQL 과 같다). `rabbitmqctl change_password` 로 바꾼다. 백엔드 · 런타임 · 브로커 셋이 같은 값이어야 한다 |
| 19 | **실행은 브로커가 살아 있어야 돈다.** 브로커가 죽어도 실행 접수(202)는 되고 outbox 에 쌓인다. 10분 안에 브로커가 돌아오면 그대로 넘어가고, 넘기지 못하면 전액 환불로 닫힌다 |

### 자주 나오는 문제

| 증상 | 원인 / 해결 |
| --- | --- |
| `This job is stuck` | Runner 태그 불일치. `.gitlab/ci/*.yml` 의 `tags:` 와 등록 태그 확인 |
| `docker: permission denied` | `sudo usermod -aG docker gitlab-runner` 후 runner 재시작 |
| 빌드 산출물이 root 소유 | `docker run` 의 `-u "$(id -u):$(id -g)"` 누락 |
| `backend:deploy` 헬스체크 실패 | 잡 로그 끝에 컨테이너 로그가 찍힌다. 대개 Flyway 마이그레이션 또는 DB 접속 실패 |
| `MYSQL_PASSWORD 가 비어 있습니다` | 변수 미설정, 또는 Protected 인데 `master` 가 보호 브랜치가 아님 |
| MySQL 3306 이 외부에 열림 | `-f compose.prod.yaml` 누락, 또는 Compose 2.24 미만 |
| `npm ci` 가 EACCES | 컨테이너 `HOME` 미설정. `-e HOME=/workspace/.npm-home` 확인 |
| `rsync: Permission denied` | `sudo chown -R gitlab-runner:gitlab-runner /var/www/j15a403` |
| 새로고침 시 404 | Nginx `try_files ... /index.html` 누락 |
| 배포했는데 화면 그대로 | 브라우저 캐시 또는 `index.html` 캐시 헤더 |
| 403 Forbidden | 상위 디렉터리 실행 권한: `chmod 755 /var/www` |
| API 404 | Nginx `/api/` 프록시 블록, `proxy_pass` 끝 슬래시 확인 |
| 로그인 후 바로 로그아웃 | `AUTH_COOKIE_SECURE=true` 인데 HTTP 접속. 또는 `WALLET_AUTH_DOMAIN` 불일치 |
| 추천 컨테이너가 기동 중 죽음 | `/opt/abc/models` 가중치 누락 → [§ 4.3](#43-추천-서비스-가중치--인덱스-필수) |
| AI 배포가 "백엔드 네트워크를 찾지 못했습니다" | 백엔드를 먼저 배포. 또는 `BACKEND_NETWORK` 지정 |
| AI 배포가 "Docker 볼륨 … 이 없습니다" | RabbitMQ · 결과 볼륨이 들어간 백엔드를 먼저 배포 |
| `RABBITMQ_USERNAME 가 비어 있습니다` | GitLab 변수 미설정, 또는 Protected 인데 `master` 가 보호 브랜치가 아님 |
| 실행이 `QUEUED` 에서 멈춤 | 런타임 health 의 `broker`, 관리 UI 의 `abc.runs.submit` 컨슈머 수. 백엔드 · 런타임 · 브로커 계정이 같은지 |
| 계정을 바꿨는데 브로커 접속 실패(`ACCESS_REFUSED`) | 계정은 첫 기동 때만 만들어진다 → `rabbitmqctl change_password` (§ 5 의 18) |
| 실행이 `FILE_PATH_REJECTED` 로 실패 | 런타임의 file-store 마운트가 `ai-block-clock_file-store` 인지 |

### 롤백

`frontend:build` 의 artifacts 가 1주일 보관된다. 파이프라인 화면에서 이전 커밋의 build 잡 →
**Job artifacts > Download** 로 받아 서버에 풀거나, 해당 커밋에서 **Run pipeline** 을 다시 돌린다.

### 7.3 DB 계정

운영 서버에서 확인한 값이다 (2026-09-28).

| 계정 | 용도 | 비고 |
| --- | --- | --- |
| `root@%`, `root@localhost` | 컨테이너 초기화 · 덤프 | `MYSQL_ROOT_PASSWORD` |
| **`admin@%`** | 애플리케이션 접속 | `MYSQL_USER` / `MYSQL_PASSWORD` |

| 항목 | 운영 값 | `compose.yaml` 기본값 |
| --- | --- | --- |
| DB 이름 | **`ai-block-clock`** (하이픈) | `ai_block_clock` (밑줄) |
| 계정 | **`admin`** | `ai_block_clock` |

접속 문자열 (compose 가 조립, 운영 실측):

```
jdbc:mysql://mysql:3306/ai-block-clock?useSSL=false&allowPublicKeyRetrieval=true&serverTimezone=Asia/Seoul
```

> 이름이 기본값과 다르니 **새 서버에 올릴 때 GitLab 변수 `MYSQL_DATABASE` · `MYSQL_USER` 를
> 반드시 같이 옮긴다.** 빠뜨리면 기본값으로 빈 DB 가 만들어지고, 덤프를 넣을 곳이 달라진다.
