# 3. 시연 시나리오

> 한 줄 요약 — **한 번의 실행이 세 판매자의 수익이 된다.** 이것이 ABC 가 다른 서비스와 다른 점이고,
> 시연은 이 문장을 눈으로 보여주는 것이 목표다.

| 항목 | 값 |
| --- | --- |
| 주소 | https://j15a403.p.ssafy.io |
| 브라우저 | Chrome + MetaMask 확장 |
| 소요 | 약 12분 (전체) / 7분 (축약) |
| 필요 계정 | 판매자 A · B · C, 사용자, 관리자 — 지갑 5개 |

## 0. 시연 전 준비 (전날까지)

### 0.1 계정 · 지갑

| 역할 | 준비할 것 |
| --- | --- |
| 판매자 A 김전략 | 지갑 · 가입 완료. "브랜딩 전략" 에이전트 **공개 상태** |
| 판매자 B 이마케터 | 지갑 · 가입 완료. "SNS 캠페인 기획" · "통합 실행안" 에이전트 공개 |
| 판매자 C 박카피 | 지갑 · 가입 완료. "광고 카피" 에이전트 공개 |
| 사용자 최사장 | 지갑 · 가입 완료. **abcToken 보유** (충전 시연용 여유분 포함) |
| 관리자 | 지갑 주소가 `ADMIN_WALLET_ADDRESSES` 에 들어가 있을 것 |

MetaMask 에 **SSAFY 네트워크**(체인 31221, RPC `https://rpc.ssafy-blockchain.com`, 기호 SSF)를
미리 추가하고, 시연용 계정으로 전환해 둔다. → [02-외부서비스 § 4](02-외부서비스.md#4-metamask)

### 0.2 자료

- 칫솔 브랜드 기획 브리프 (포화 시장용 / 틈새용 두 벌 — 분기 시연에 쓴다)
- 칫솔 시제품 사진 1장 (파일 업로드 시연)
- 내 서식용 회사 보고서 디자인 PDF 1장 (서식 시연)

### 0.3 시스템 점검 (당일 아침)

```bash
curl -I  https://j15a403.p.ssafy.io/              # 200
curl -fsS http://127.0.0.1:8080/actuator/health   # {"status":"UP"}
curl -fsS http://127.0.0.1:8000/v1/health         # {"status":"ok"}
curl -fsS http://127.0.0.1:8100/health            # 200
```

- **등급 재산정**은 새벽 3시에 한 번 돈다. 직전에 데이터를 바꿨다면
  `AGENT_GRADE_REGRADE_CRON` 을 가까운 시각으로 잠깐 바꿔 한 번 돌린다.
- **추천 인덱스**에 시연 에이전트가 들어 있는지 확인한다. 비었으면 추천 화면이 빈손으로 나온다.
- 브라우저 캐시를 비우고, MetaMask 는 **SSAFY 네트워크 · 사용자 계정**으로 맞춰 둔다.

## 1. 전체 흐름

```
 ① 로그인 (지갑 서명)      /login
 ② 판매자 — 노드 만들고 잇고 판다   /edit/nodes → /register
 ③ 사용자 — 충전            /my/credit
 ④ 사용자 — 말로 찾기        /  →  /edit/searching
 ⑤ 사용자 — 캔버스에 잇기     /edit/nodes
 ⑥ 사용자 — 견적 · 실행       /run/waiting → /run/:id/running
 ⑦ 결과 — 서식 고르고 PDF
 ⑧ 정산 확인               /my/sales ×3
 ⑨ 출금 신청 → 관리자 승인    /my/sales → Swagger
```

## 2. 단계별 상세

### ① 로그인 — 비밀번호가 없다 (1분)

| # | 화면 | 어디를 누르나 | 무슨 일이 일어나나 |
| --- | --- | --- | --- |
| 1 | `/login` | 가운데 **「MetaMask 지갑 연결」** 버튼 | MetaMask 팝업이 뜬다 |
| 2 | MetaMask | 계정 선택 → **연결** | 지갑 주소가 프론트에 전달된다 |
| 3 | MetaMask | 서명 요청 창에서 **서명** | 백엔드가 발급한 nonce 메시지에 서명한다. 화면에는 "지갑에서 서명을 기다리는 중" |
| 4 | – | – | 백엔드가 서명을 검증하고 **세션 쿠키**를 발급한다 |
| 5 | `/signup` | 처음이면 이름 · 한 줄 소개 입력 → **저장** | 기존 회원이면 이 화면을 건너뛰고 홈으로 간다 |

> **말할 것** — "비밀번호가 없습니다. 지갑 서명 한 번이 로그인입니다. 서명 메시지에는
> 도메인과 체인 ID 가 들어 있어서 다른 사이트에서 가로채 쓸 수 없습니다."
>
> **막히면** — 서명이 거절되면 화면에 "서명이 거절되었습니다" 가 뜬다. 다시 누르면 된다.
> 다른 네트워크에 붙어 있으면 상단에 배너가 뜨니 배너의 전환 버튼을 누른다.

### ② 판매자 — 노드를 이어 에이전트를 만든다 (3분)

판매자 A 계정으로 로그인한 상태에서 진행한다.

| # | 화면 | 어디를 누르나 | 보여줄 것 |
| --- | --- | --- | --- |
| 1 | `/my/agents` | **「워크플로우 만들기」** | 빈 캔버스(`/edit/nodes`)가 열린다 |
| 2 | `/edit/nodes` 오른쪽 **노드 팔레트** | 노드 추가 | 이름 · **프롬프트** · 모델 · 출력 형식(글 또는 JSON 예시)을 적는다 |
| 3 | 캔버스 | 노드를 끌어다 놓고 **점과 점을 이어** 연결 | 시작 · 종료 · 조건 분기 노드도 팔레트에 있다 |
| 4 | 캔버스 | 분기 노드 설정 | 앞 노드가 JSON 으로 낸 칸(`doc_type`)의 값을 보고 길을 고른다 |
| 5 | 상단 | **「저장」** | "저장됨" 표시. 워크플로우가 남는다 |
| 6 | 노드 정보 패널 | **테스트 실행** | 원가(Base Cost)를 잰다. 판매자에게 무료, 노드당 하루 5회 |
| 7 | 상단 | **「등록하기」** → `/register` | "마켓에 등록하시겠습니까?" 확인 |
| 8 | `/register` | 한 줄 설명 · 상세 설명 · 입력 예시 입력 → **등록** | "등록 완료". 버전이 굳고 판매가가 매겨진다 |

> **말할 것 (핵심 3개)**
> 1. **"코딩이 없습니다."** 프롬프트와 참고 파일만 적으면 블록이 된다.
> 2. **"프롬프트는 저장 뒤 누구에게도 보이지 않습니다."** 판매자의 노하우가 봉인된다.
> 3. **"가격을 판매자가 정하지 않습니다."** 플랫폼이 테스트 실행으로 잰 원가에
>    에이전트 등급(Tier)의 할증을 붙여 정한다.
>
> **막히면** — 남의 노드나 에이전트가 섞인 워크플로우는 등록할 수 없다("판매 등록 불가").
> 시연에서는 본인이 만든 노드만 쓴다.

### ③ 사용자 — abcToken 충전 (1분 30초)

사용자(최사장) 계정으로 전환한다. **MetaMask 에서 계정을 바꾼 뒤 다시 로그인**한다.

| # | 화면 | 어디를 누르나 | 무슨 일이 일어나나 |
| --- | --- | --- | --- |
| 1 | 우상단 프로필 메뉴 | **「충전/출금」** → `/my/credit` | 현재 ABC 잔액이 보인다 |
| 2 | `/my/credit` | 금액 입력 → **「충전하기」** | "충전할 금액을 입력하세요" |
| 3 | MetaMask | 전송 승인 | abcToken 을 **보관 지갑 `0x64e7…B6B6`** 으로 보낸다. 가스비 0 |
| 4 | 화면 | 대기 | 백엔드가 체인에서 입금을 확인한다. 블록이 약 10초마다 생기고 confirmation 1 이면 인정 |
| 5 | `/my/credit` | 내역 확인 | 충전이 **거래 해시**와 함께 남는다 |

> **말할 것** — "화면의 숫자와 체인의 거래가 1:1 로 대응합니다. 서버가 임의로 적은 값이
> 아니라, 체인에서 확인한 입금만 ABC 가 됩니다."
>
> **막히면** — 30분 안에 블록에 안 적히면 실패로 닫힌다. 늦게 성사되면 같은 해시로 다시
> 요청하면 된다. 시간이 급하면 이 단계를 **미리 충전해 둔 잔액**으로 대신하고 내역만 보여준다.

### ④ 말로 찾기 — 추천 (1분)

| # | 화면 | 어디를 누르나 | 보여줄 것 |
| --- | --- | --- | --- |
| 1 | `/` (홈) | 가운데 입력란에 자연어로 적는다 | "칫솔 브랜드 전략 세우고 SNS 캠페인까지 뽑고 싶어" |
| 2 | `/` | **「파일 선택하기」** (선택) | 칫솔 시제품 사진을 붙인다 |
| 3 | – | 엔터 / 전송 | `/edit/searching` 전환 화면 → 추천 엔진이 **뜻으로** 찾는다 (8개 안쪽) |
| 4 | 추천 목록 | 쓸 에이전트를 **차례로 클릭** | "선택한 순서대로 연결됩니다" |

> **말할 것** — "이름에 그 단어가 없어도 찾습니다. 키워드 검색이 아니라 문장의 뜻을
> 임베딩으로 견줍니다. 키워드로 찾고 싶으면 마켓(`/search`)에서 검색하면 됩니다."
>
> **막히면** — 추천이 비면 상단 메뉴의 **마켓(`/search`)** 으로 가서 카드에서 직접 고른다.
> 카드에는 만든 사람 · 사용 횟수 · 실행 단가가 적혀 있다.

### ⑤ 캔버스에 잇기 (1분 30초)

| # | 화면 | 어디를 누르나 | 보여줄 것 |
| --- | --- | --- | --- |
| 1 | `/edit/nodes` | 추천받은 에이전트가 **순서대로 이어진 채** 놓여 있다 | 맨 앞 `[기획 요청서]`, 맨 뒤 `[출력]` 은 플랫폼이 자동으로 붙인 것 |
| 2 | 오른쪽 목록 | 다른 마켓 에이전트를 **끌어다 놓기** | 남의 에이전트도 나누고 합칠 수 있다 |
| 3 | 캔버스 | 갈래로 잇기 | A → (B ∥ C) → B 모양을 만든다 |
| 4 | 상단 | **「저장하고 실행 화면으로 갑니다」** | `/run/waiting` 으로 넘어간다 |

목표 모양:

```
[기획 요청서]
   → [브랜딩 전략 · 김전략(A)] ─┬─▶ [SNS 캠페인 기획 · 이마케터(B)] ─┐
                               └─▶ [광고 카피 · 박카피(C)]        ─┤ 둘 다 받아
                                                                   ▼
                                           [통합 실행안 · 이마케터(B)] → [출력]
```

> **말할 것** — "김전략의 에이전트는 밖에서 블록 하나지만, 실행되면 **안의 다섯 노드와
> 분기가 그대로** 돕니다. 세 사람의 블록이 한 줄로 이어졌습니다."

### ⑥ 견적 · 실행 (2분)

| # | 화면 | 어디를 누르나 | 무슨 일이 일어나나 |
| --- | --- | --- | --- |
| 1 | `/run/waiting` | 입력 폼을 채운다 | 첫 블록의 입력 예시에 맞춰 **항목별 입력란이 자동 생성**된다 (브랜드명 · 카테고리 · 핵심 고객 · 가격대 · 차별점 · 추가 요청). JSON 을 직접 쓸 일이 없다 |
| 2 | `/run/waiting` | 파일 첨부 | 시제품 사진. 여러 개, 합계 10MB. **모든 블록이 본다** |
| 3 | `/run/waiting` | **견적** 확인 | 단계별 비용 · 예상 비용 · 내 잔액이 나온다. "이 실행은 최대 N ABC" |
| 4 | `/run/waiting` | **「실행하기」** | 견적만큼 **먼저 차감**한다(선차감) |
| 5 | `/run/:id/running` | 지켜본다 | 블록에 차례로 불이 들어온다. SSE 로 실시간 |
| 6 | 캔버스 | **분기에서 한쪽만 밝아진다** | 포화 시장 브리프(칫솔)는 **차별화 전략** 길로 간다 |

> **말할 것 (여기가 하이라이트)**
> - "**안 간 길은 돈을 받지 않습니다.** 두 갈래를 다 더해 먼저 떼고, 안 간 쪽 몫은 돌려줍니다."
> - "화면을 닫아도 실행은 계속됩니다. 결과는 실행 내역에 남습니다."
> - "분기 판정은 AI 가 아니라 **플랫폼**이 합니다. 앞 노드가 JSON 으로 낸 칸의 값을 비교합니다."
>
> **시간이 남으면** — 틈새 브리프로 한 번 더 돌려 **같은 에이전트가 다른 길**(대중 공략)로
> 가는 것을 보여준다. 이게 분기의 의미를 가장 빨리 전달한다.
>
> **막히면** — 전체가 길어도 5분 안에 끝난다. 그 이상 걸리면 미리 돌려 둔 실행 내역
> (`/my/usage`)에서 완료된 건을 열어 결과 화면부터 이어간다.

### ⑦ 결과 — 서식을 고르고 PDF (1분 30초)

| # | 화면 | 어디를 누르나 | 보여줄 것 |
| --- | --- | --- | --- |
| 1 | `/run/:id/running` | "실행 완료" | 결과가 먼저 **데이터(JSON 또는 글)** 로 있다 |
| 2 | 결과 영역 | **서식 선택** — 플랫폼 기본 | 문서형 · 카드형. 고른 서식을 입힌 HTML 이 화면에 바로 뜬다 |
| 3 | 결과 영역 | **「결과 다운로드 (PDF)」** | HTML 을 PDF 로 뽑는다. 한글 폰트(나눔)가 임베딩된다 |
| 4 | 서식 목록 | **내 서식** 올리기 | 회사 보고서 디자인 PDF 를 올리면 AI 가 **빈칸 뚫린 서식**으로 바꿔 보관한다 |
| 5 | 결과 영역 | 내 서식으로 다시 받기 | 같은 데이터, 다른 옷 |

> **말할 것** — "서식을 입히는 데는 **AI 가 없습니다.** 0.2초, 0원, 몇 번을 돌려도 같은 결과입니다.
> 내 디자인을 올릴 때 **딱 한 번** AI 를 부르고, 그 뒤 1,000번 실행해도 그대로 재사용합니다."
>
> **막히면** — 서식이 데이터와 안 맞으면 기본 서식으로 대신 만든다. **서식 문제가 실행을
> 실패시키지 않는다** — 블록은 이미 성공했고 정산도 끝났기 때문이다.

### ⑧ 정산 — 세 사람의 수익 (1분)

| # | 화면 | 누구로 | 보여줄 것 |
| --- | --- | --- | --- |
| 1 | `/my/usage` | 사용자 | 충전한 ABC 와 실행에 쓴 ABC 가 **실행 번호와 함께** 남는다 |
| 2 | `/my/sales` | 판매자 A | 정산금 추이 · 판매 금액 · 호출 수 |
| 3 | `/my/sales` | 판매자 B | 두 에이전트(SNS 캠페인 · 통합 실행안) 몫이 각각 |
| 4 | `/my/sales` | 판매자 C | 광고 카피 몫 |

> **말할 것** — "**한 번의 실행이 세 사람의 수익이 됐습니다.** 성공한 단계만큼만 정산하고,
> 안 간 분기와 실패한 단계는 사용자에게 돌려줍니다. 돈은 전부 백엔드 장부가 셉니다."

축약 시연이면 판매자 A 하나만 열어도 된다.

### ⑨ 출금 · 관리자 심사 (1분 30초)

| # | 화면 | 누구로 | 어디를 누르나 |
| --- | --- | --- | --- |
| 1 | `/my/sales` | 판매자 | **「출금 신청」** — 출금 가능 정산금 · 출금 금액 선택 · 받을 지갑 확인 |
| 2 | – | 판매자 | 본인 확인(신원 확인) 정보를 제출한다 |
| 3 | `/api/swagger-ui.html` | **관리자** | `POST /api/v1/admin/identity-verifications/{id}/...` 로 본인 확인 승인 |
| 4 | `/api/swagger-ui.html` | **관리자** | `POST /api/v1/admin/withdrawals/{id}/...` 로 출금 **승인** 또는 **반려** |
| 5 | 체인 | – | 보관 지갑이 abcToken 을 판매자 지갑으로 보낸다 |
| 6 | `/my/sales` | 판매자 | 출금 내역에 **거래 해시**가 남는다 |

> **관리자 화면은 따로 없다.** Swagger UI 로 심사한다(`API_DOCS_ENABLED=true`).
> 관리자 지갑으로 먼저 로그인해 세션 쿠키를 받아야 `/api/v1/admin/**` 이 열린다
> (`ADMIN_WALLET_ADDRESSES` 에 그 주소가 있어야 한다).
>
> **운영 서버는 지급이 켜져 있다** (2026-09-28 확인: 보관 지갑 키 설정됨,
> `PAYMENT_WITHDRAWAL_PAYOUT_ENABLED=true`). **승인하면 실제로 abcToken 이 체인에서
> 옮겨가고 되돌릴 수 없다.** 리허설에서 함부로 승인하지 않는다.
>
> 반대로 키가 없는 환경(로컬 · 새 서버)에서는 승인해도 `APPROVED` 에서 멈췄다.
> 오류가 아니라 설계된 동작이다.
>
> 제약: 최소 1 ABC · 최대 1000 ABC, 마지막 신청에서 24시간이 지나야 다시 신청할 수 있다
> (`PAYMENT_WITHDRAWAL_REQUEST_INTERVAL`). **시연 직전 리허설에서 출금을 한 번 신청했다면
> 24시간 제한에 걸린다.** 다른 판매자 계정으로 시연하거나 값을 잠시 `0` 으로 둔다.

## 3. 축약 시연 (7분)

시간이 없으면 이 순서로 자른다.

| 순서 | 내용 | 시간 |
| --- | --- | --- |
| 1 | 로그인 (지갑 서명) | 40초 |
| 2 | 판매자 캔버스 — **이미 만들어 둔 것을 열어서** 구조와 분기만 설명 | 1분 |
| 3 | 홈에서 말로 찾기 → 추천 → 자동 연결 | 1분 |
| 4 | 견적 → 실행 → **분기에서 한쪽만 밝아지는 순간** | 2분 30초 |
| 5 | 결과 PDF | 40초 |
| 6 | 판매자 3명 정산금 | 1분 |

②의 노드 생성과 ⑨의 출금 심사를 뺀다. 충전은 **이미 충전된 잔액과 내역**으로 대신한다.

## 4. 장애 대비

| 상황 | 대응 |
| --- | --- |
| LLM 응답이 느리다 | 미리 돌려 둔 실행을 `/my/usage` 에서 열어 결과 화면부터 이어간다 |
| 추천이 빈손으로 나온다 | 마켓(`/search`)에서 직접 고른다. 추천 인덱스는 시연 전에 반드시 확인 |
| 추천 품질이 이상하다 | `ABC_HYBRID=off` 로 즉시 되돌린다 (컨테이너 환경변수, 재기동) |
| 지갑 서명이 계속 거절된다 | MetaMask 잠금 해제 · SSAFY 네트워크인지 · 계정이 맞는지 확인 |
| 충전이 확인되지 않는다 | 블록 10초 간격. 30초 기다려도 안 되면 미리 충전한 잔액으로 넘어간다 |
| 실행이 실패한다 | 실패 판정과 환불 규칙을 **설명 소재로 쓴다** — 누구 잘못인지 플랫폼이 자동으로 가린다 |
| 출금이 `APPROVED` 에서 멈춘다 | 지급 스위치가 꺼진 상태. 화면에서 상태 전이(신청 → 승인)까지만 보여준다 |
| 화면이 갱신되지 않는다 | SSE 가 끊기면 폴링으로 넘어간다. 새로고침해도 실행은 계속된다 |

### 실패 판정 규칙 (질문이 나오면)

| 상황 | 판정 | 사용자 ABC | 판매자 |
| --- | --- | --- | --- |
| 입력은 맞았는데 노드가 틀린 모양으로 답하거나 시간 초과 | **판매자 잘못** | 그 노드분 + 뒤에 안 돈 것 환불 | 정산 없음, 성공률 하락 |
| 필수 항목을 비웠거나 올린 파일을 읽을 수 없음 | **사용자 잘못** | 이미 성공한 노드분은 지불 | 성공한 노드는 정산 유지 |
| 앞 결과가 상한을 넘김 · 플랫폼 오류 | **플랫폼 잘못** | 전액 환불 | 영향 없음 |

> 비유: 재료를 제대로 줬는데 요리사가 태우면 요리사 잘못, 상한 재료를 주면 주문자 잘못,
> 주방에 불이 나면 식당 잘못.
