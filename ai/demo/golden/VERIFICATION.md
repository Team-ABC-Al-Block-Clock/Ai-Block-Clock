### G3 — 분기 조건이 뒤집히는 지점

분기 조건은 **`avg_delta < 0`** 이다. 정확히 0이면 격려형이어야 한다.
5명은 전 과목 +2, 5명은 전 과목 −2로 만들어 합이 정확히 상쇄되게 했다.

### G4 — 값의 경계

| 학생 | 노리는 것 |
| --- | --- |
| 경계상승 · 경계하락 | `avg_delta` 가 **정확히 ±1.00**. `trend` 임계값의 등호 유무 |

## 2. 왜 시연 데이터만으로는 부족한가

**통과하는 테스트는 그 자체로는 아무것도 증명하지 않는다.** 틀린 구현도 통과시킬 수
있기 때문이다. 그래서 구현을 일부러 세 가지 방식으로 망가뜨려 **어느 케이스가
잡아내는지**를 확인했다.

| 일부러 심은 오류 | G1 | G2 | **G3** | **G4** |
| --- | :---: | :---: | :---: | :---: |
| 분기 조건을 `avg_delta <= 0` 으로 | 통과 | 통과 | **잡힘** | 통과 |
| `trend` 임계값에서 등호를 뺌 (`> 1.0` / `< -1.0`) | 통과 | 통과 | 통과 | **잡힘** |
| `weak_subject` 를 최고점 과목으로 | 통과 | 통과 | 통과 | **잡힘** |

```
분기 조건을 <= 0 으로 잘못 구현
   G3  분기 warn  기대 encourage  → 잡힘

trend 임계값에서 등호를 뺌
   G4  경계상승.trend 기대 up / 실제 flat  → 잡힘

weak_subject 를 최고점 과목으로
   G4  동점최저.weak_subject 기대 국어 / 실제 수학  → 잡힘
```

**시연 데이터(G1 · G2)는 세 오류를 하나도 잡지 못한다.** 평균이 −5.40, +4.96 으로
조건에서 멀찍이 떨어져 있어 부등호를 어떻게 쓰든 같은 답이 나오기 때문이다.
경계 케이스를 따로 만든 이유가 이것이다.

## 3. 원본 엑셀 대조 (AI-08-5)

### 기대값과 검증이 같은 코드를 쓰면 아무것도 검증하지 못한다

기대값을 `analyze()` 로 만들고 검증도 `analyze()` 로 하면, **같은 코드가 같은 답을
낸다는 사실만 확인**하게 된다. 그 코드의 평균 공식이 틀렸다면 기대값도 똑같이 틀린다.

그래서 엑셀 대조는 **완전히 다른 경로**로 계산한다.

```
경로 A   roster.json → analyze()          → summary
경로 B   xlsx 셀     → openpyxl 로 직접 합산 → summary
                      (JSON 도 analyze() 도 거치지 않음)
```

`run_golden_cases.py` 의 `excel_totals()` 가 경로 B다. 엑셀에서 `(이번달)` ·
`(지난달)` 열을 직접 읽어 파이썬 기본 연산으로 합계를 낸다. 두 경로가 독립적이라야
한쪽의 실수가 드러난다.

### 대조 결과 — 4개 케이스 전부 일치

| 케이스 | 학생 수 | `avg_previous` | `avg_current` | `avg_delta` |
| --- | ---: | ---: | ---: | ---: |
| G1 | 20 | 74.26 | 68.86 | −5.40 |
| G2 | 20 | 74.58 | 79.54 | +4.96 |
| G3 | 10 | 74.50 | 74.50 | 0.00 |
| G4 | 8 | 69.38 | 68.12 | −1.25 |

엑셀에서 직접 낸 값과 분석 결과가 소수 둘째 자리까지 일치한다.

### 검증 도구 자체의 결함 — 거짓 통과 (2026-09-15 수정)

첫 버전은 `openpyxl` 이 설치돼 있지 않으면 **엑셀 대조를 한 번도 하지 않고도
"분석 결과가 원본 엑셀 계산값과 일치한다"고 단언했다.** 로컬 실행에서 발견했다.

원인은 두 가지를 구분하지 못한 것이다.

| 상태 | 첫 버전의 표현 | 실제 의미 |
| --- | --- | --- |
| 대조했고 문제가 없었다 | 빈 목록 | 통과 |
| 대조를 **못 했다** | 빈 목록 취급 | **아무것도 확인되지 않음** |

`excel_totals()` 가 두 경우 모두 falsy 값을 돌려줬고, 통과 판정이 문자열
매칭(`"건너뜀" not in p`)으로 "건너뜀"을 무해한 것으로 처리하고 있었다.

**고친 내용**

- `excel_totals()` 는 대조 불가 시 `None` 을 돌려준다 (빈 dict 와 구분)
- `run_case()` 가 `excel_checked` 를 따로 반환한다
- 한 케이스라도 대조를 못 했으면 **exit code 1** 과 함께
  "AI-08-5 수치 정합성은 아직 확인되지 않은 상태다" 를 출력한다

**교훈.** 검증 도구가 낼 수 있는 가장 나쁜 결과는 실패가 아니라 **거짓 통과**다.
실패는 눈에 띄지만 거짓 통과는 아무도 다시 보지 않는다. 확인하지 못한 것을
통과로 세는 경로가 있는지 먼저 봐야 한다.
