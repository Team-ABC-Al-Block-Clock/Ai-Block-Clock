### 후보별 결과

- **jhgan/ko-sroberta-multitask** — Recall@3 1.00 / 1등 정답 5/5 / MRR@3 1.000 / 격차 **0.179** / 30ms / 로딩 6.1초 / 768d
  - 절대 점수는 낮지만(0.36~0.78) 정답과 오답을 가장 크게 벌려놓음
  - ⚠️ 최대 입력 **128토큰** — 실제 시드 에이전트 설명 + 스키마 필드를 붙이면 잘릴 위험

- **intfloat/multilingual-e5-base** — Recall@3 1.00 / 1등 정답 5/5 / MRR@3 1.000 / 격차 **0.033** / 32ms / 로딩 8.3초 / 768d
  - 점수가 0.78~0.88 좁은 구간에 몰림. 1·2등 차이가 최소 0.010까지 붙음
  - e5 계열의 알려진 특성(고득점 구간 압축). 에이전트가 늘면 순위 역전 위험
  - 2등에 '가정통신문 작성기'가 5건 중 3건 등장 — 변별력 낮음 신호
  - `query:` / `passage:` 접두어 적용 상태로 측정

- **nlpai-lab/KURE-v1** — Recall@3 1.00 / 1등 정답 **4/5** / MRR@3 **0.900** / 격차 0.097 / 85ms / 로딩 7.9초 / 1024d
  - ⚠️ "학원 애들 점수가 얼마나 올랐는지" 질의에서 **1등이 오답**
    (가정통신문 0.499 vs 성적분석 0.494 — 0.005 차로 역전)
  - 세 모델 중 1등을 놓친 유일한 모델. **Recall@3으로는 이 결함이 안 보임**
  - 모델 2.27GB → 서빙 메모리 1.5GB 상한 초과 가능 (가이드 §12.3 선정 기준 ③)
  - 질의 지연도 2.8배 (85ms vs 30ms)

### 관찰

1. **단어가 겹치지 않아도 정답이 잡힌다.** "부모님께 보낼 안내문" → "가정통신문 작성기"가 세 모델 모두에서 1등.
   키워드 검색으로는 불가능한 매칭이며, 임베딩 방식의 타당성이 확인됨 (MKT-002 근거)

2. **Recall@3만으로는 모델을 선정할 수 없다.** 세 후보가 전부 1.00으로 동점.
   1등 정답률과 MRR을 추가하자 KURE-v1이, 1·2등 격차를 추가하자 e5-base가 갈렸다.
   → **지표 설계가 곧 선정 근거.** 골든 쿼리와 MRR 도입 필요성이 실측으로 확인됨 (MKT-003 근거)

3. **크고 최신인 모델이 우리 문제에 더 맞지는 않았다.** 한국어 검색 특화 대형 모델(KURE-v1)이
   경량 SBERT보다 1등 정답률·격차·지연 모두에서 밀림. 에이전트 20~30개 규모에서는
   모델 용량보다 **정답/오답 변별력**이 중요하다는 방향

4. **모델 로딩 6~8초 vs 질의 30ms — 약 200배 차이.**
   FastAPI lifespan에서 1회만 로드하는 설계(가이드 §12.7)의 정량 근거

### 선정 — `jhgan/ko-sroberta-multitask` · 스키마 설명 **제외**

| 기준 (가이드 §12.3) | 판정 |

| ① Recall@5 · MRR | **1.00 / 1.000 — 22개 질의 전부 1등.** 다른 후보보다 명확히 앞섬 |

**스키마 설명을 빼기로 한 이유.** 포함/제외가 품질은 동점(둘 다 만점)인데, 제외 쪽이
격차가 더 크고(0.115 vs 0.096) **128토큰 잘림이 사라진다.** 09-08에는 스키마 설명이
도움이 됐지만, 카탈로그 설명문 자체를 개선하자 그 역할이 필요 없어졌다.
→ **모델을 데이터에 맞추는 대신, 데이터를 고쳐서 제약을 없앤 사례.**

**라이선스 확인 (2026-09-09 조사)**

- 원 저장소 `jhgan00/ko-sentence-transformers`는 **CC-BY-SA-4.0**
- 학습 데이터는 카카오브레인 KorNLU(KorNLI · KorSTS), 기반 모델은 `klue/roberta-base`
- NC(비영리) 조항이 없어 **상업 이용 자체는 가능**하나, **출처 표기(BY)** 와

- 학내 프로젝트·시연 범위에서는 문제없다. 발표 자료와 README에 출처를 명시한다

### 한계 — 만점의 함정

**1등 정답률과 MRR이 모두 만점이라, 이 세트로는 파인튜닝 효과를 보일 수 없다.**
올라갈 여지가 0이기 때문이다. 원인은 두 가지로 본다.

- 에이전트 20개 · 질의 22개 · Top-5 는 문제가 쉽다
- 시드 카탈로그와 골든 쿼리를 같은 사람이 작성해, 질의가 설명문과 잘 맞는 편향이 있다

→ 09-10 파인튜닝 평가는 아래 두 축으로 바꾼다.

- **홀드아웃 세트**: 합성 질의 420개 중 80개를 학습에서 제외하고 평가 전용으로 사용
  (골든 쿼리 22개는 회귀 확인용으로 유지)
- **주 지표를 1·2등 격차로**: 순위는 이미 만점이므로, 하드 네거티브 학습이
  정답과 오답을 얼마나 더 벌려놓는지를 본다. 0.115 → 얼마나 커지는가
