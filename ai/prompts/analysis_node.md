## 이 프롬프트의 어려운 점 — 산술이다

출력 `edu.analysis@1` 은 **전부 숫자**다. 학생 20명 × 과목 4개 = **80개 값을 평균 내고
빼는 일**을 LLM이 해야 한다. 판단이 들어가는 자리가 없는 대신, **틀리면 그냥 틀린다.**

그래서 이 프롬프트의 목표는 문장을 잘 쓰는 게 아니라 **계산 규칙을 빠짐없이,
해석의 여지 없이 적는 것**이다. "평균을 내라"가 아니라 "무엇을 무엇으로 나누는가"를
쓴다.

그리고 맞았는지는 **채점기로 확인한다.** `ai/demo/analysis_reference.py` 가
같은 규칙을 파이썬으로 구현한 정답 계산기다. 프롬프트 출력을 이 값과 대조한다.

> ★ **아래 System 프롬프트의 계산 규칙과 `analysis_reference.py` 는 한 글자도
> 달라서는 안 된다.** 두 곳에 규칙이 흩어지면 "프롬프트는 이렇게 시켰는데 채점은
> 저렇게 한" 상태가 되어 준수율 숫자가 거짓말이 된다.

## System

<!-- prompt:analysis -->
```
당신은 학원 성적 데이터를 집계하는 계산기입니다.

주어진 JSON의 숫자만으로 결과를 만드세요. 추정하거나 보간하지 마세요.
데이터에 없는 학생, 과목, 점수를 만들어내면 안 됩니다.

계산 규칙:
- 학생의 평균은 그 학생의 전 과목 점수 합을 과목 수로 나눈 값입니다.
- 전체 평균은 모든 학생의 모든 과목 점수 합을 (학생 수 × 과목 수)로 나눈 값입니다.
- delta = current - previous 입니다. 소수 둘째 자리에서 반올림합니다.
- weak_subject 는 그 학생의 이번 달 점수가 가장 낮은 과목입니다.
  동점이면 subjects 배열에서 먼저 나오는 과목을 고릅니다.
- trend 는 그 학생의 avg_delta 로 정합니다.
    avg_delta >= 1.0   -> "up"
    avg_delta <= -1.0  -> "down"
    그 사이            -> "flat"

출력에 설명, 인사말, 코드블록 표시를 넣지 마세요. JSON만 출력합니다.
students 배열의 순서는 입력 순서를 그대로 유지합니다.
```

## User

<!-- prompt:analysis_user -->
```
아래는 한 학원의 두 달치 성적 데이터입니다. 집계해 주세요.

{roster_json}
```

`{roster_json}` 자리에 앞 노드가 낸 `edu.roster@1` payload 를 넣는다.

> **`context.comment`(원장 코멘트)는 넣지 않는다.** 집계에 쓸 값이 아니고,
> 넣으면 모델이 코멘트의 표현에 끌려가 숫자를 왜곡할 수 있다.
> 그 문장은 가정통신문 프롬프트에서만 쓴다.

## 기대 출력 형태

```jsonc
{
  "summary": {
    "student_count": 20,
    "avg_current": 68.86,
    "avg_previous": 74.26,
    "avg_delta": -5.40
  },
  "students": [
    { "name": "강윤슬", "avg_current": 72.25, "avg_delta": 6.50,
      "weak_subject": "과학", "trend": "up" }
  ],
  "subjects": [
    { "name": "국어", "avg_current": 69.75, "avg_delta": -4.55 }
  ]
}
```

## 준수율 목표 — 09-20 까지 **95% 이상**

이 프롬프트는 문장이 아니라 **숫자**를 내므로, 스키마 통과만으로는 부족하다.
값이 맞는지까지 본다.

```bash
cd ai/demo
python run_golden_cases.py --impl <출력.json> --case G1
```

| 검사 | 왜 보는가 |
| --- | --- |
| `summary` 4개 값 | 이 중 `avg_delta` 가 분기를 가른다. 틀리면 실행 경로가 바뀐다 |
| 학생 수 · 이름 일치 | 빠뜨리거나 없는 학생을 만들어내는 실패 |
| `avg_current` · `avg_delta` | 소수 둘째 자리까지 대조 |
| `weak_subject` · `trend` | 동점 처리와 임계값 등호를 지켰는가 |

골든 케이스 4개 중 **G3 · G4 가 경계값**이다. 정상 데이터만으로는 부등호 오류가
드러나지 않는다 — 근거는 `ai/demo/golden/VERIFICATION.md` §2.

미달이면 계산 규칙 문장을 고치고 다시 잰다. **고칠 때는
`analysis_reference.py` 의 규칙도 같이 고친다.**
