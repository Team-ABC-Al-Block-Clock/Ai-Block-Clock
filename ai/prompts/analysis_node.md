## ⚠️ 먼저 읽을 것 — 이 노드는 LLM이 필요하지 않다

`edu.analysis@1` 의 **모든 필드가 산술로 결정된다.**

| 필드 | 어떻게 정해지는가 |
| --- | --- |
| `summary.student_count` | 학생 수 세기 |
| `summary.avg_current` · `avg_previous` · `avg_delta` | 평균, 뺄셈 |
| `students[].avg_current` · `avg_delta` | 학생별 평균, 뺄셈 |
| `students[].weak_subject` | 이번 달 점수 최솟값인 과목 |
| `students[].trend` | `avg_delta` 부호 (`up` / `flat` / `down`) |
| `subjects[].avg_current` · `avg_delta` | 과목별 평균, 뺄셈 |

**판단이 들어가는 자리가 한 곳도 없다.** 그런데 학생 20명 × 과목 4개 = **80개 숫자를
평균 내는 일**을 LLM에게 시키면 틀린다. 그리고 AI-08-5 수치 정합성 가드가 그 오류를
잡아내면 — 시연 중에 잡아내면 — 그때 할 수 있는 게 없다.

로드맵 W3 수요일 항목에도 *"밀렸다면 분석 노드를 LLM 없이 파이썬 계산으로 대체"* 가
적혀 있다. **이것을 최후 수단이 아니라 기본값으로 하자는 것이 트랙 B의 제안이다.**

- 가이드 §7.2 원칙: **"판정은 코드, 제안은 모델"** 과도 맞는다
- H2A · A2A2H 도 이미 LLM 없는 노드다. 이 노드만 예외인 게 아니다
- 시연에서 "AI를 쓴다"는 인상은 **가정통신문 노드**가 만든다. 그쪽은 진짜 글을 쓴다
- 계산 노드는 응답이 수십 ms 이고 비용이 0원이다. 5분 예산에도 유리하다

레퍼런스 구현: **`ai/demo/analysis_reference.py`**
이 파일은 결정적 계산이면서, 동시에 **AI-08-5 수치 정합성 가드의 기준값**이다.
LLM으로 가더라도 이 값과 대조해야 하므로 어느 쪽이든 필요하다.

### ★ 노드를 없애자는 말이 아니다

**노드는 그대로 두고 안을 계산으로 채운다.** 분석 노드를 H2A에 합쳐 3노드로 줄이면
시연 에이전트가 하나가 되고, 금요일 관문 ④ **"한 번의 실행으로 서로 다른 두 계정에
정산금이 적립됨"** 을 보여줄 수 없다. 로드맵 §2.3에서 유일하게 *"반드시 지킨다"* 로
못 박은 항목이다. 정산금이 없는 것은 I/O 노드뿐이고(팀 합의 N-4), 분석 노드는
I/O 노드가 아니라 일반 노드다 — LLM을 쓰지 않아도 정산 대상이다.

> **트랙 B 결정 (09-15).** 분석 노드는 **결정적 계산**으로 간다.
> 구현은 `ai/demo/analysis_reference.py` 의 `analyze()` 를 그대로 쓰면 된다.

## ⓑ 대안 — LLM으로 가야 할 경우의 프롬프트

### 필수 실행 조건

- **구조화 출력 강제** (AI-02-3). `edu.analysis@1` JSON Schema 를 `response_format` 에 건다.
  프롬프트로 "JSON으로 답해줘"라고 부탁하는 것으로는 부족하다
- **temperature 0.** 같은 입력에 같은 결과가 나와야 리허설이 의미가 있다
- 교정 재요청 2회 (AI-02-4), 타임아웃 60초 (AI-02-5)

### System

```
당신은 학원 성적 데이터를 집계하는 계산기입니다.

주어진 JSON의 숫자만으로 결과를 만드세요. 추정하거나 보간하지 마세요.
데이터에 없는 학생, 과목, 점수를 만들어내면 안 됩니다.

계산 규칙:
- 학생의 평균은 그 학생의 전 과목 점수 합을 과목 수로 나눈 값입니다.
- 전체 평균은 모든 학생의 모든 과목 점수 합을 (학생 수 × 과목 수)로 나눈 값입니다.
- delta = current - previous 입니다. 소수 둘째 자리에서 반올림합니다.
- weak_subject 는 그 학생의 이번 달 점수가 가장 낮은 과목입니다.
  동점이면 subjects 배열에서 먼저 나오는 과목을 고릅니다.
- trend 는 그 학생의 avg_delta 로 정합니다.
    avg_delta >= 1.0   -> "up"
    avg_delta <= -1.0  -> "down"
    그 사이            -> "flat"

출력에 설명, 인사말, 코드블록 표시를 넣지 마세요. JSON만 출력합니다.
students 배열의 순서는 입력 순서를 그대로 유지합니다.
```

### User

```
아래는 한 학원의 두 달치 성적 데이터입니다. 집계해 주세요.

{roster_json}
```

`{roster_json}` 자리에 상위 노드(H2A)의 `payload` 를 그대로 바인딩한다 (AI-02-2).

> **`context.comment` 는 이 노드에 넣지 않는다.**
> 원장의 코멘트는 집계에 쓸 값이 아니고, 가정통신문 노드에서만 필요하다.
> 여기 넣으면 모델이 코멘트의 표현에 끌려가 숫자를 왜곡할 수 있다.
> 데이터 최소 전달 원칙(AI-05-5)이기도 하다.

### 기대 출력 형태

```jsonc
{
  "summary": {
    "student_count": 20,
    "avg_current": 68.86,
    "avg_previous": 74.26,
    "avg_delta": -5.40
  },
  "students": [
    { "name": "강윤슬", "avg_current": 72.25, "avg_delta": 6.50,
      "weak_subject": "과학", "trend": "up" }
  ],
  "subjects": [
    { "name": "국어", "avg_current": 70.15, "avg_delta": -4.30 }
  ]
}
```

## 분기가 여기서 갈린다

이 노드의 `summary.avg_delta` 가 다음 분기의 조건식이다 (팀 합의 R-01 · C-3).

```
summary.avg_delta < 0   ->  경고형 가정통신문 노드
그 외                    ->  격려형 가정통신문 노드
```

분기 조건식은 **숫자 비교 하나**로 끝난다 (AI-01-5 축소 결정). 그래서 이 필드 하나만
정확하면 분기는 안전하다. 반대로 **이 숫자가 틀리면 시연이 통째로 다른 길로 간다.**
LLM에 맡기지 말자는 근거가 하나 더 있는 셈이다.

## 시연 데이터

| 파일 | `avg_delta` | 타는 분기 |
| --- | --- | --- |
| `ai/demo/data/demo_roster_down.xlsx` | **−5.40** | 경고형 ← **시연 본편** |
| `ai/demo/data/demo_roster_up.xlsx` | +4.96 | 격려형 ← 반대 경로 확인용 |

두 파일은 **학생 명단과 과목이 같고 점수만 다르다.** 결과가 달라진 이유를
분기 하나로 설명할 수 있게 하기 위해서다.
