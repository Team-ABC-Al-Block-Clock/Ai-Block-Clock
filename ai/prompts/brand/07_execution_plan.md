# ⑦ 통합 실행안 프롬프트 (S15P21A403-276)

| 항목 | 내용 |
| --- | --- |
| 노드 | 2단계 · 판매자 B 의 에이전트 · **종단 노드** |
| 입력 → 출력 | `{ campaign: biz.campaign_plan@1, copy: biz.ad_copy@1 }` → `biz.execution_plan@1` |
| 합류 | ⑤와 ⑥이 **둘 다 끝나야** 실행된다 |
| 기준 | 스키마 통과율 ≥ 95% · **두 입력에 없는 채널·카피 0건** |

---

## ⭐ 1. 이 노드의 유일한 실패 방식 — 한쪽만 보고 나머지를 지어낸다

앞선 전략 초안 노드처럼 이 노드도 입력을 두 개 받는다. **한쪽 입력만 읽고 나머지를
지어내는지 확인해야 한다.** 캠페인 계획만 자세히 읽고 카피는
"적당히 있을 법한 문구"를 만들어 넣는 식이다.

이게 왜 치명적인가. 시연의 요점이 **"서로 다른 판매자의 에이전트가 이어 붙어 하나의
결과를 만든다"** 인데, ⑦이 ⑥을 안 읽으면 판매자 C 의 에이전트는 실행된 의미가 없다.
화면에는 카피 비슷한 글이 떠 있지만 그건 ⑦이 지어낸 것이다.

**게다가 이건 조용히 실패한다.** 결과물은 멀쩡해 보인다. 두 입력과 대조하지 않으면
아무도 모른다.

그래서 이 노드는 **"만들지 말고 옮겨라"** 를 가장 강하게 건다. 인용 문구와 해시태그는
문자열로 대조한다. 인용하지 않은 새 문구나 알려지지 않은 채널은 사람도 확인해야 한다.

## 2. 합류 노드는 새로 만들 게 거의 없다

⑤가 일정과 채널을, ⑥이 문구를 이미 만들었다. ⑦이 할 일은 **둘을 시간 축 위에
배치하고 빠진 것을 점검표로 남기는 것**이다.

새 아이디어를 넣을 자리가 없다는 뜻이고, 그게 맞다. 합류 지점에서 새 방향이 나오면
앞 두 노드의 결과가 무의미해진다.

[가장 중요한 규칙 — 만들지 말고 옮긴다]
이 단계에서 새로 만드는 것은 없다. 두 입력에 이미 있는 것을 시간 순서로 배치하는 일이다.
  · 채널은 캠페인 계획의 channels 에 있는 것만 쓴다. 다른 채널을 추가하지 않는다.
  · 문구는 광고 카피의 headlines · body_copies 에 있는 것만 쓴다. 새로 쓰지 않는다.

  · 해시태그는 광고 카피의 hashtags 에 있는 것만 쓴다.
    각 항목의 tag 값을 그대로 쓴다.

두 입력을 다 읽었는지 스스로 확인한다. 카피 쪽을 읽지 않고 그럴듯한 문구를 지어내는
실수가 가장 흔하다. 실행안에 등장하는 모든 문구는 받은 카피에서 찾을 수 있어야 한다.

[각 항목 작성 지침]
- summary_md: 3~5문장. 마크다운 허용.
  이 실행안이 무엇을 언제까지 하는 것인지 한눈에 들어오게 쓴다.
  캠페인 목표(objective)와 카피의 톤(tone)이 어떻게 맞물리는지 한 문장 넣는다.
  예산을 배분해야 한다면 금액이 아니라 비중으로 쓴다 ("초기 2주에 집중" 등).
  받은 입력에 금액이 없으므로 금액을 만들지 않는다.

- phases: 2~4개. 시간 순서대로.
  period 는 기간("1~2주차", "출시 후 첫 달" 등).
  actions 는 그 기간에 할 일 2~5개. 각각 한 줄 문장이다.
  actions 에는 **어느 채널에 무엇을 올리는지**가 들어가야 한다.
  채널명과 문구는 두 입력에서 가져온다.

- checklist: 3~8개. 실행 전에 확인할 것.
  label 만 있는 한 줄 항목이다.
  "무엇이 준비되지 않으면 이 실행안이 멈추는가"를 기준으로 고른다.
  캠페인 계획의 kpis 를 어떻게 측정할지도 하나 넣는다.

- 브랜드 전략을 다시 논하지 않는다. 이미 정해진 것을 실행하는 단계다.
- 카피를 다듬거나 고치지 않는다. 받은 문구 그대로 쓴다.

## 4. 채점 기준

| # | 항목 | 실패 조건 |
| --- | --- | --- |
| ① | **없는 채널** | `phases[].actions` 에 `campaign.channels[].name` 에 없는 채널명이 등장 |
| ② | **없는 문구** | 따옴표로 인용된 문구가 `copy.headlines[]`·`copy.body_copies[]` 에 없음 |
| ③ | **없는 해시태그** | `#` 로 시작하는 문자열이 `copy.hashtags[]` 에 없음 |
| ④ | **카피 미사용** | `copy.headlines` 중 어느 것도 실행안에 등장하지 않음 |
| ⑤ | 항목 수 | `phases` 2~4 · `actions` 2~5 · `checklist` 3~8 중 벗어남 |
| ⑥ | 지어낸 금액 | 금액 표현(원·만원·억원)이 등장. 비중(%)은 금액과 구분해 사람이 확인 |
| ⑦ | 카피 변형 | 인용된 문구가 원본과 글자 단위로 다름 (다듬어 씀) |
| ⑧ | KPI 누락 | `checklist` 에 `campaign.kpis` 측정 관련 항목이 없음 |

**①~④가 대표 지표다.** 자동 검사는 알려진 채널명·큰따옴표 인용 문구·해시태그와
원본 헤드라인 사용 여부를 대조한다. 사전에 없는 채널, 인용하지 않은 새 카피,
문구의 의미 변형은 사람이 확인해야 하므로 자동 통과를 전체 내용 준수로 보지 않는다.

**특히 ④를 빠뜨리면 안 된다.** ①~③은 "없는 것을 만들었는가"를 보지만, ④는
"있는 것을 썼는가"를 본다. 카피를 하나도 안 쓰고 채널만 나열해도 ①~③은 통과한다.
그건 판매자 C 의 에이전트가 헛돈 것이다.

### 미달일 때 고치는 순서

1. ④가 걸리면 → user 블록의 "두 가지를 모두" 지시를 더 강하게. 카피를 먼저 읽도록 순서를 바꿔 본다
2. ①~③이 걸리면 → system 의 "만들지 말고 옮긴다" 를 각 항목 지침에도 반복해 넣는다
3. ⑦이 걸리면 → "받은 문구 그대로" 를 fewshot 예시로 보여 준다
