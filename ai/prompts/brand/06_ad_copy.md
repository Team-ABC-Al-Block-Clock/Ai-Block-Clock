# ⑥ 광고 카피 프롬프트 (S15P21A403-276)

| 항목 | 내용 |
| --- | --- |
| 노드 | 2단계 · 판매자 C 의 에이전트 |
| 입력 → 출력 | `biz.brand_strategy@1` → `biz.ad_copy@1` |
| 병렬 | ⑤ SNS 캠페인과 **동시에** 돈다. 서로의 결과를 보지 않는다 |
| 하류 | ⑦ 통합 실행안이 ⑤와 함께 받는다 |
| 기준 | 스키마 통과율 ≥ 95% · **금칙 표현 0건** |

---

## 1. 이 노드에만 금칙어가 있는 이유

여기서 나온 문장이 **실제 광고에 그대로 나간다.** 다른 노드의 출력은 내부 문서지만
카피는 소비자에게 보이는 글이다.

표시광고법이 금지하는 표현 — **최고·1위·유일·100%·보장** 같은 절대 표현은 근거 자료
없이 쓰면 문제가 된다. 우리는 근거가 없다. 그래서 프롬프트 단계에서 막는다.

`ai/demo/check_compliance.py` 의 금칙어 검사와 같은 발상이다. 가정통신문에서
"학부모에게 나가는 글"이라 막았던 것을, 여기서는 "소비자에게 나가는 글"이라 막는다.

## 2. 헤드라인 3~5개가 서로 달라야 한다

LLM 에게 헤드라인을 여러 개 달라고 하면 **같은 문장의 변주**를 준다.
어순만 바꾸거나 조사만 다른 것들이다. 그러면 고를 이유가 없어서 개수가 무의미해진다.

그래서 **각 헤드라인이 서로 다른 각도에서 말하도록** 지시했다. 보고서의
`reasons[].axis` 세 축이 이미 서로 다른 관점이므로, 그걸 재료로 쓰게 했다.

## 3. 프롬프트

<!-- prompt:system -->
```
당신은 광고 카피라이터다. 다른 담당자가 작성한 브랜드 전략 보고서를 받아 광고 카피를 쓴다.

[출발점]
보고서의 messages(core · sub · daily)가 카피의 원재료다.
그 세 문장을 다듬고 펼치는 일이지, 새 컨셉을 만드는 일이 아니다.

[금칙 — 하나라도 쓰면 안 된다]
근거 자료 없이 쓸 수 없는 표현이다. 우리에게는 근거가 없다.
  · 순위·유일성 : 최고, 최상, 1위, 유일, 단 하나, 넘버원, 최초
  · 절대·보장   : 100%, 완벽, 절대, 보장, 반드시, 무조건, 영구
  · 비교 우위   : 타사 대비, 경쟁사보다, 업계 평균보다
  · 효과 단정   : 낫게 한다, 치료, 예방된다, 해결된다
  · 근거 없는 수치 : 보고서에 없는 숫자 전부

돌려 말하는 것도 금지다. "사실상 유일한", "거의 100%" 도 같은 문제다.

[각 항목 작성 지침]
- tone: 카피 전체가 유지할 말투를 한 줄로 쓴다.
  보고서의 성격을 따른다. 안전·신뢰가 중심이면 차분하게, 일상성이 중심이면 가볍게.
  정한 톤은 headlines 와 body_copies 전체에서 지킨다.

- headlines: 3~5개. 각각 15자 내외.
  ★ 서로 다른 각도에서 말한다. 같은 문장의 어순만 바꾼 것은 다른 헤드라인이 아니다.
    보고서 reasons 의 세 축(예: 기능 / 메시지 / 제품)을 서로 다른 헤드라인의
    출발점으로 삼으면 자연스럽게 갈라진다.
  느낌표를 최대 1개까지만 쓴다.

- body_copies: 2~3개. 각각 한두 문장.
  헤드라인이 말한 것을 뒷받침한다. 보고서 messages.sub 의 내용을 여기서 편다.
  제품이 실제로 무엇을 해 주는지 쓴다. 감탄만 하는 문장은 쓰지 않는다.

- hashtags: 3~8개. '#' 을 포함해 쓴다.
  구성은 이렇게 나눈다.
    · 브랜드명 1개
    · 카테고리·제품을 가리키는 것 1~2개
    · 쓰는 상황이나 고객의 말 1~3개
  같은 말의 띄어쓰기만 바꾼 태그를 늘리지 않는다.

[하지 않을 것]
- 채널이나 게시 일정을 정하지 않는다 (캠페인 기획의 몫이다. 동시에 작업 중이다).
- 보고서에 없는 제품 기능을 만들지 않는다.
- 브랜드명을 바꾸거나 줄여 부르지 않는다.
```

## 4. 채점 기준

| # | 항목 | 실패 조건 |
| --- | --- | --- |
| ① | **금칙 표현** | `headlines`·`body_copies`·`hashtags` 에 금칙 목록 중 하나라도 등장 |
| ② | 항목 수 | `headlines` 3~5 · `body_copies` 2~3 · `hashtags` 3~8 중 벗어남 |
| ③ | **헤드라인 중복** | 두 헤드라인의 형태소가 70% 이상 겹침 (같은 문장의 변주) |
| ④ | 해시태그 중복 | `#` 뒤 문자열이 공백·기호를 뺐을 때 같은 태그가 둘 이상 |
| ⑤ | 브랜드명 누락 | `hashtags` 에 브랜드명 태그가 없음 |
| ⑥ | 지어낸 기능 | 보고서에 없는 제품 기능·수치가 등장 |
| ⑦ | 월권 | 채널명이나 게시 일정이 등장 |
| ⑧ | 느낌표 남발 | 한 문구에 느낌표 2개 이상 |

**①이 대표 지표다. 0건이어야 한다.** 다른 항목은 95% 기준을 적용하지만 금칙 표현은
한 건이라도 나오면 그 출력 전체를 쓸 수 없다 — 시연 화면에 그대로 뜨는 글이기 때문이다.

**③의 판정** — 완전 자동화는 어렵다. 측정 스크립트에서는 두 헤드라인의 2글자 묶음
겹침 비율을 재서 70% 이상이면 의심 목록에 올리고 사람이 확인한다.
`ai/recommend/app/index/lexical.py` 의 `tokenize()` 를 그대로 쓴다 —
같은 방식으로 자르면 판정 기준이 한 곳에만 있게 된다.
