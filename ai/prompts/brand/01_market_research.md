## 1. 이 노드가 특별한 이유 — 분기가 여기서 갈린다

`competition_level` 하나로 워크플로우가 갈라진다.

```
competition_level == "high"  →  ③a 차별화 전략
competition_level == "low"   →  ③b 대중 공략 전략
```

**이 값이 흔들리면 시연이 무너진다.** 리허설에서는 차별화 전략이 나왔는데 본 시연에서
대중 공략이 나오면, 준비한 설명이 전부 어긋난다. 다른 노드는 문장이 조금 달라져도
넘어갈 수 있지만 여기는 아니다.

### 왜 "포화된 시장이면 high" 라고 쓰면 안 되는가

LLM 은 확률적으로 답한다. **"포화"처럼 사람마다 기준이 다른 말을 쓰면 호출할 때마다
경계가 움직인다.** 같은 브리프에 high 와 low 가 번갈아 나온다.

그래서 판정을 **셀 수 있는 것**으로 바꿨다.

```
1) competitors 에 실제로 떠오르는 전국 유통 브랜드만 적는다 (스키마 상한 5개)
2) N = competitors 의 개수
3) N == 5 → high · N <= 4 → low
```

### 09-26 수정 — 세는 대상을 오프라인 일반 매장으로 좁혔다 (트랙 A가 인수 후 수정)

기본 모델이 `gemini-2.5-pro`로 바뀐 뒤, low 브리프(클라이밍 테이프)가 3회 중 2회 high 로 나왔다.
competitors 에 Evolv · Black Diamond · Metolius 같은 **해외 클라이밍 전문 브랜드**가 5칸을 채웠다.
규칙의 "온라인 종합몰"을 근거로, 온라인에서 살 수 있는 전문 브랜드를 전부 전국 유통으로 본 것이다.
아래 3절 "미달일 때 고치는 순서" 3번(세는 대상을 좁힌다 — 유통 채널을 못박는다)을 그대로 적용해
**오프라인 일반 매장 진열대**로 좁히고, 전문점 · 온라인 전용 브랜드를 명시적으로 뺐다.

### 09-22 수정 — 세는 것과 적는 것을 묶었다

처음에는 "떠오르는 대로 센 개수"로 판정하게 했다. 09-22 실호출에서 이렇게 나왔다.

```
level_reason : "전국 유통 브랜드 5개를 확인했다"
competitors  : 3개
```

**센 개수와 적은 개수가 다르다.** 나열을 건너뛰고 숫자만 말한 것이고, 그러면 절차가
아니라 다시 인상 판정이다. 애초에 피하려던 문제로 돌아온다.

그래서 **판정을 `competitors` 배열 길이에 묶었다.** 스키마가 이미 최대 5개로 막아두고
있으니, "5칸을 다 채울 만큼 있느냐"가 곧 판정이 된다.

이렇게 하면 **출력만 보고 판정이 맞는지 기계적으로 검증된다.** 예전에는 `level_reason`
의 숫자와 배열 길이가 어긋나도 아무도 몰랐지만, 묶어두면 어긋날 수가 없다.

남는 위험은 하나다 — **LLM 은 배열을 최대치까지 채우려 한다.** 그래서 "칸을 채우려고
만들어 내지 않는다"를 강하게 넣고, fewshot 에 3개만 적은 예를 보여 준다.
시연 브리프도 5개를 채우는 게 불가능한 카테고리로 골랐다.

시연 브리프 두 개는 경계(5개)에서 멀리 떨어뜨려 골랐다 — 칫솔은 한참 위,
반려견 LED 하네스는 한참 아래다. 자세한 건 `ai/demo/brand/README.md` 참고.

## 3. 채점 기준

준수율 측정에서 아래 중 하나라도 걸리면 그 호출은 실패로 센다.

| # | 항목 | 실패 조건 |
| --- | --- | --- |
| ① | **분기 안정성** | 같은 브리프 10회에서 `competition_level` 이 하나라도 다름 |
| ② | 판정 근거 형식 | `level_reason` 이 `전국 유통 브랜드 N개를 확인했다.` 로 시작하지 않음 |
| ③ | **판정-배열 일치** | `level_reason` 의 N ≠ `len(competitors)`, 또는 `competition_level` 이 규칙(N==5→high)과 어긋남 |
| ④ | 경쟁사 수 | `competitors` 가 2~5개를 벗어남 (스키마가 막지만 같이 센다) |
| ⑤ | 자기 자신 | `competitors` 에 요청서의 `brand_name` 이 들어감 |
| ⑥ | 지어낸 수치 | 점유율·매출·성장률 같은 검증 불가 수치가 `market_overview_md` 에 등장 |
| ⑦ | 요청 위반 | `comment` 에서 하지 말라고 한 것을 함 |

**①이 대표 지표다.** 나머지는 ①이 무너졌을 때 원인을 좁히기 위한 것이다.
②·③을 넣은 이유가 그것이다 — 값만 보면 왜 뒤집혔는지 알 수 없지만, 센 개수가 남아 있으면
"7개로 세다가 4개로 셌다"까지 좁혀진다.

### 미달일 때 고치는 순서

한 번에 하나씩 고치고 다시 잰다. 두 개를 같이 고치면 무엇이 효과가 있었는지 못 가린다.

1. ③이 걸리면 → 판정 규칙의 부등호를 더 또렷하게 (경계값 예시를 fewshot 에 추가)
2. ②가 걸리면 → fewshot 의 첫 문장 형식을 더 강하게 지시
3. ①만 걸리고 ②·③은 통과면 → **N 자체가 흔들리는 것이다.** 세는 대상 정의
   ("전국 유통 브랜드")를 더 좁힌다. 예: 유통 채널을 하나로 못박는다

## 4. 알려진 한계

- **모델이 아는 브랜드에 의존한다.** 웹 검색을 하지 않으므로 최신 신규 브랜드는 못 센다.
  시연 범위에서는 문제가 없다 — 두 브리프 모두 경계에서 멀다
- **N 을 세는 것 자체는 검증할 수 없다.** 우리가 보는 것은 "일관되게 세는가"이지
  "정확히 세는가"가 아니다. 분기 조건으로 쓰는 데는 일관성이면 충분하다
- 경계(5개) 근처 카테고리에서는 값이 흔들릴 수 있다. **시연 브리프를 바꾸려면
  `competition_level` 10회 측정을 다시 해야 한다**
