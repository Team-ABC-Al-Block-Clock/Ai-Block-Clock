> 기획서 6-④의 원식은 1~5 스케일의 평점(R_bayes)과 0~100 스케일의 사용량(U_norm)을 스케일 보정 없이 그대로 가중합해, 사용량이 평점을 사실상 압도한다. 이 문서의 R_norm 정규화가 그 결함을 고친 것이다. 백엔드 구현 시 원식이 아니라 이 문서 기준으로 작성한다.

## 1. 개별 지표 가공

### 1.1 평점 베이지안 보정

```
R_bayes = (v × R + m × C) / (v + m)
```

| 기호 | 의미 | 값 |
| --- | --- | --- |
| `v` | 해당 에이전트의 평가(리뷰) 횟수 | 실측 |
| `R` | 해당 에이전트의 평균 평점 (1~5) | 실측 |
| `m` | 보정 강도 (가상 평가 횟수) | **10** (초기값, 🔶 팀 합의 필요) |
| `C` | 전체 평균 평점 (사전 확률) | **3.5** (초기값, 🔶 팀 합의 필요. 실제 리뷰가 쌓이면 전체 평균으로 교체 권장) |

평가가 적은 신규 에이전트가 우연히 5점 하나로 최상위에 뜨는 것을 막는다. `v`가 커질수록 `R_bayes`는 실제 평균 `R`에 수렴한다.

### 1.2 평점 스케일 정규화 🔶

```
R_norm = (R_bayes − 1) / 4 × 100
```

1~5점 스케일을 0~100으로 바꿔 사용량 지표와 같은 스케일에서 가중합한다. **이 정규화가 없으면 사용량이 평점을 압도하는 기획서 원식의 결함이 그대로 남는다.**

### 1.3 사용량 로그 정규화

```
U_norm = log10(U + 1) / log10(U_max) × 100
```

| 기호 | 의미 | 값 |
| --- | --- | --- |
| `U` | 해당 에이전트의 누적 성공 실행 횟수 | 실측 |
| `U_max` | 정규화 상한 (콜드스타트 고정 목표치) | **1,000** (초기값). 상위 에이전트의 실제 사용량이 이를 넘으면 실측값으로 교체 |

로그를 쓰는 이유: 사용량은 선형이 아니라 초기 성장이 크고 이후 완만해지는 게 자연스럽다. 선형으로 두면 사용량 격차가 점수를 지나치게 벌린다.

### 1.4 성공률

```
S = 성공 실행 수 / (성공 실행 수 + 공급자 책임 실패 수)
```

- 실행 0건이면 `S = 1`로 둔다 (콜드스타트 시 Tier 4 유지 목적의 허들 장치).
- **공급자 책임(`fault = supplier`) 실패만 분모에 포함한다.** 수요자 책임(`consumer`)과 플랫폼 책임(`platform`) 실패는 집계하지 않는다. 판정 기준은 인수인계 §5 및 `ai-runtime-api.md` §4.2를 따른다.
- 결과물의 **품질**은 성공률이 아니라 평점(§1.1)이 담당한다. 성공률은 "약속한 대로 동작했는가"만 본다.

## 2. 종합 점수

```
Score = (W1 × R_norm + W2 × U_norm) × S^k
```

| 기호 | 값 |
| --- | --- |
| `W1` (평점 가중치) | 0.6 |
| `W2` (사용량 가중치) | 0.4 |
| `k` (성공률 지수) | 2 |

성공률은 가중합 항이 아니라 **곱셈 항**이다. 성공률이 낮으면 평점 · 사용량이 아무리 높아도 점수가 급격히 깎인다(`S^2`이므로 S=0.9면 0.81배, S=0.5면 0.25배).

## 3. 등급 — MVP는 절대평가

| Tier | Score 구간 🔶 | 필수 허들 | Premium Rate |
| --- | --- | --- | --- |
| 1 Platinum | ≥ 80 | S ≥ 0.98, 평가 50회 이상 | +50% |
| 2 Gold | ≥ 65 | S ≥ 0.95, 평가 20회 이상 | +30% |
| 3 Silver | ≥ 45 | S ≥ 0.90 | +10% |
| 4 Bronze | 그 외 · 신규 | 없음 | +0% |

**등급 결정 순서.** Score 구간으로 1차 후보 Tier를 정한 뒤, 그 Tier의 허들(성공률 · 평가 횟수)을 만족하는지 확인한다. **허들을 만족하지 못하면 허들을 만족하는 최고 Tier로 강등한다.** 예: Score 82(Platinum 구간)인데 평가 30회뿐이면 → Platinum 허들(50회) 미충족 → Gold 허들(20회) 확인 → 충족 → Gold로 확정.

Score 구간 경계값(80/65/45)은 초기 제안이며 🔶 실제 에이전트 분포를 보고 팀이 조정할 수 있다. 상대평가(백분위) 전환은 v2(PAY-028)에서 다룬다.

## 4. 실행 단가

```
단가 = Base Cost × (1 + Premium Rate)
```

- `Base Cost`는 NOD-007(노드 단독 테스트 3회 실측 원가 평균) · AGT-006(에이전트는 내부 노드 Base Cost 합산, 분기가 있으면 경로 중 최댓값)에서 산출된다. 이 문서의 범위 밖이다.
- Premium의 공급자/플랫폼 배분은 OI-03(70/30 권장)이나, **MVP는 수수료 0%로 전액 공급자**에게 돌아간다.

## 5. 콜드스타트 정책 — 검산 예시

시연 시점 에이전트는 평점 · 사용량이 전부 0이라 그대로면 전부 Tier 4, Premium +0%가 되어 자동 등급 · 단가 산정이 화면에 드러나지 않는다. **시연 에이전트 1개에만 아래 시드 값을 주입한다.**

| 값 | 계산 |
| --- | --- |
| `v = 25, R = 4.6` | `R_bayes = (25 × 4.6 + 10 × 3.5) / 35 = 4.29` → `R_norm = (4.29 − 1) / 4 × 100 = 82.1` |
| `U = 120` | `U_norm = log10(121) / log10(1000) × 100 = 69.4` |
| `S = 0.96` | `S² = 0.92` |
| **종합** | `Score = (0.6 × 82.1 + 0.4 × 69.4) × 0.92 ≈ 71.0` |

**판정.** Score 71.0 → 1차 후보 Gold(≥65) 구간. 허들 확인: S(0.96) ≥ 0.95 ✅, v(25) ≥ 20회 ✅ → **Tier 2 Gold, Premium +30% 확정.**

**나머지 시연 에이전트 1개는 시드 없이 Tier 4로 둔다.** 그러면 화면에 등급 차이(Gold vs Bronze)와 단가 차이가 함께 보인다. 시드 주입은 백엔드가 DB에 직접 넣거나 배치 스크립트로 처리한다(구현은 백엔드 몫).

**검증 방법.** 백엔드가 위 시드 값으로 계산했을 때 Score ≈ 71.0, Tier 2가 나오면 구현이 이 문서와 일치하는 것으로 본다.

## 6. 재산정 주기

등급과 단가는 정해진 주기로 재산정한다(PAY-022). 주기와 트리거(배치 스케줄 vs 이벤트 기반)는 백엔드가 운영 편의에 맞춰 정한다. 재산정 시 변경 사항은 공급자와 해당 에이전트를 사용 중인 수요자에게 반영되어야 한다(요구사항 PAY-022).
