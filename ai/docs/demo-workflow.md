# 시연 워크플로우 구성 — 확정안

| 항목 | 내용 |
| --- | --- |
| 관련 이슈 | `S15P21A403-271` · `-273` (트랙 B 산출물) → `S15P21A403-262` (트랙 A 재구성) |
| 요구사항 | EXE-006 · NOD-006 · PAY-012 |
| 작성 | 트랙 B · 2026-09-15 |
| 용도 | 트랙 B가 만든 프롬프트 · 데이터를 트랙 A에 넘기기 위한 한 장 |

트랙 A가 바쁜 상황이라 **트랙 B가 먼저 정하고 넘긴다.** 아래는 결정된 것으로 보고
진행하면 되고, 다르게 가야 할 이유가 있으면 알려주면 트랙 B가 맞춘다.

---

## 1. 노드 구성 — 4노드를 유지한다

```
① H2A            ② 분석             ③ 가정통신문        ④ A2A2H
  엑셀 → JSON  →   집계 → 통계   →   통계 → 편지 20통  →  편지 → PDF
                          │
                          └─ 분기: summary.avg_delta < 0 ?
```

| | 노드 | 입력 | 출력 | LLM | 담당 |
| --- | --- | --- | --- | :---: | --- |
| ① | H2A | `.xlsx` + 원장 코멘트 | `edu.roster@1` | ✕ | A |
| ② | **분석** | `edu.roster@1` | `edu.analysis@1` | **✕** | 로직 B · 실행 A |
| ③ | 가정통신문 | `edu.analysis@1` + 코멘트 | `edu.letter@1` | ○ | 프롬프트 B · 실행 A |
| ④ | A2A2H | `edu.letter@1` | PDF 1장 | ✕ | A |

### ⚠️ 3노드로 줄이면 안 되는 이유

시연 에이전트 **2개**(분석 · 가정통신문)를 **서로 다른 팀원 계정**으로 등록하는 것이
`S15P21A403-275` 이고, 그래야 금요일 관문 ④ **"한 번의 실행으로 서로 다른 두 계정에
정산금이 적립됨"** 이 성립한다. 로드맵 §2.3에서 유일하게 *"반드시 지킨다"* 로 못 박은
항목이다.

**분석 노드를 H2A에 합치면 시연 에이전트가 하나가 되고, 두 계정 적립을 보여줄
방법이 사라진다.** 정산금이 없는 것은 I/O 노드뿐이고(팀 합의 N-4), 분석 노드는
I/O 노드가 아니라 일반 노드라 해당하지 않는다.

## 2. 분석 노드는 LLM을 쓰지 않는다

`edu.analysis@1` 의 모든 필드가 산술로 결정된다. 판단이 들어가는 자리가 한 곳도 없다.

| 필드 | 정해지는 방식 |
| --- | --- |
| `summary.student_count` | 학생 수 |
| `summary.avg_current` · `avg_previous` · `avg_delta` | 평균, 뺄셈 |
| `students[].avg_current` · `avg_delta` | 학생별 평균, 뺄셈 |
| `students[].weak_subject` | 이번 달 최저 점수 과목 |
| `students[].trend` | `avg_delta` 부호 |
| `subjects[].avg_current` · `avg_delta` | 과목별 평균, 뺄셈 |

그런데 학생 20명 × 과목 4개 = **80개 숫자를 평균 내는 일**을 LLM에게 시키면 틀린다.
더 중요한 건 **`summary.avg_delta` 하나로 분기가 갈린다**는 점이다. 이 숫자가 틀리면
시연이 통째로 다른 경로로 간다.

- 가이드 §7.2 원칙 **"판정은 코드, 제안은 모델"**
- H2A · A2A2H 도 이미 LLM 없는 노드다. 이 노드만 예외인 게 아니다
- 응답 수십 ms · 비용 0원. 5분 예산(AI-08-6)에도 유리하다
- "AI가 일한다"는 인상은 ③ 가정통신문 노드가 만든다. 그쪽은 실제로 글을 쓴다

**구현: `ai/demo/analysis_reference.py` 의 `analyze()` 를 그대로 쓰면 된다.**
입력 `edu.roster@1` dict, 출력 `edu.analysis@1` dict. 의존성 없음.

> LLM으로 가야 할 사정이 있으면 `ai/prompts/analysis_node.md` 에 프롬프트가 있다.
> 그 경우 **출력을 반드시 `analysis_reference.py --check` 로 대조해야 한다.**
> 어느 쪽을 택하든 이 파일은 수치 정합성 가드(`S15P21A403-272`)로 필요하다.

## 3. 분기

```
edu.analysis@1 의 summary.avg_delta < 0   →  ③-warn      (경고형)
그 외                                      →  ③-encourage (격려형)
```

숫자 비교 하나로 끝난다 (AI-01-5 축소 결정). 팀 합의 R-01 · C-3.

### 노드의 톤과 편지의 톤은 다르다

전체가 하락해도 **개인은 오른 학생이 있다.** 시연 데이터에도 하락 16명 / 상승 4명이
섞여 있다. 경고형 노드가 오른 학생에게까지 경고문을 보내면 학부모가 바로 알아챈다.

- **노드 선택** = 전체 평균 기준 (분기)
- **`letters[].tone`** = 그 학생의 `trend` 기준. `up` 이면 노드와 무관하게 `encourage`

`edu.letter@1` 이 편지마다 `tone` 을 갖는 이유가 이것이다. 프롬프트에 이 규칙이
들어가 있고, `check_compliance.py` 가 이 항목을 검사한다.

## 4. 넘기는 것

```
ai/prompts/
  analysis_node.md      ② 분석 노드 — 계산 권고 + LLM 대안 프롬프트
  letter_node.md        ③ 가정통신문 — 격려형 · 경고형 2벌, few-shot 3개, 금칙어

ai/demo/
  analysis_reference.py ② 결정적 계산 구현 · 수치 정합성 가드
  check_compliance.py   ③ 스키마 준수율 측정
  generate_demo_data.py 데이터 재생성 (seed 고정)
  data/
    demo_roster_down.xlsx / .json    시연 본편 입력
    demo_roster_up.xlsx   / .json    반대 분기 확인용
    demo_analysis_down.json          ② 기대 출력 (정합성 기준값)
    demo_analysis_up.json
    README.md                        데이터 사전
```

### 프롬프트를 매니페스트에 넣을 때

`letter_node.md` 의 `<!-- prompt:common -->` · `<!-- prompt:encourage -->` ·
`<!-- prompt:warn -->` · `<!-- prompt:fewshot -->` 마커 바로 다음 코드 블록이
그대로 프롬프트다. **System = common + (encourage | warn)**, User = 코멘트 + 집계 + fewshot.

`check_compliance.py` 가 같은 마커를 읽어 실행하므로, 이 문서를 고치면 측정도 같이 바뀐다.
**프롬프트를 매니페스트에 복사해 넣으면 두 곳이 어긋나기 시작한다.** 가능하면
`prompt_ref` 로 이 파일을 가리키게 해달라 (팀 합의 N-7과도 맞는다).

### 실행 조건

| 노드 | 설정 |
| --- | --- |
| ② 분석 (LLM일 경우) | temperature **0** · 구조화 출력 강제 |
| ③ 가정통신문 | temperature **0.3** · 구조화 출력 강제 |

③이 0이면 20통이 전부 같은 문장이 되고, 높이면 리허설마다 결과가 달라진다.
0.3은 문장 다양성과 재현성의 절충값이다.

## 5. 시연 데이터

| 파일 | `avg_delta` | 분기 | 학생 추세 |
| --- | --- | --- | --- |
| `demo_roster_down.xlsx` | **−5.40** | 경고형 | 하락 16 · 상승 4 |
| `demo_roster_up.xlsx` | +4.96 | 격려형 | 하락 4 · 상승 16 |

**두 파일은 학생 명단과 과목이 같고 점수만 다르다.** 결과가 달라진 이유를 분기
하나로 설명할 수 있게 하기 위해서다. 명단까지 다르면 무엇 때문에 달라졌는지 못 가린다.

`generate_demo_data.py` 는 seed 가 고정돼 있어 몇 번을 돌려도 같은 숫자가 나온다.
리허설 3회(W4 수)에서 "저번엔 이랬는데"가 통해야 하기 때문이다.

**실제 학생 정보는 쓰지 않았다.** 이름 · 점수 전부 생성값이다.
