# ai/ — AI 파트 에이전트 규칙

`ai/` 아래에서 일하는 AI 코딩 에이전트(Claude Code)에게 주는 **변하지 않는 규칙**이다. 트랙 A · B 두 사람이 같은 규칙으로 일하게 하는 것이 목적이다.
지금 상태 · 일정 · 오늘 할 일은 여기 없다 — 각자의 인수인계 문서에 있다. 사람이 읽는 설명은 [`README.md`](README.md), Git 규칙 원문은 [`../git-workflow.md`](../git-workflow.md), 백엔드 · 프론트와의 계약은 [`docs/integration-guide.md`](docs/integration-guide.md).

이 파일을 고칠 때: **규칙만** 넣는다. 새로 알게 된 사실 · 상태 · 마감은 인수인계로 보낸다. 규칙이 바뀌면 그 변경을 담은 MR에서 함께 고친다.

## 0. 일하는 방식

- 한국어로 소통한다. 결론을 먼저, 근거는 요구사항 ID · 문서 절 번호 · 파일 경로로 단다.
- 모호하면 시작 전에 묻는다. 결과물이 갈리는 쟁점은 3 ~ 4개씩 묶어 한 번에. 사소한 것은 기본값을 택하고 요약에서 알린다.
- 팀 기획 문서(기획서 · 요구사항 정의서 · 기능 명세서)는 읽기 전용이다.
- `.claude/`의 훅 · 권한은 Claude Code를 **`ai/`에서 열었을 때** 적용된다. 다른 위치에서 열면 그곳의 `.claude/settings.json`이 이 폴더의 `.claude/hooks/`를 가리키게 한다.

## 1. 트랙 경계 — 누가 무엇을 정하나

| 트랙 A — 인프라 · 설계 | 트랙 B — 모델 · 콘텐츠 |
| --- | --- |
| 노드 출력 선언 형식(JSON 예시 규칙) · 워크플로우 구성 · 노드 종류 · 분기 규칙 · Runtime 실행 방식 · A2A 규격 · 백엔드 계약 · CI/배포 | 임베딩 모델 · 추천 엔진 · 시드 에이전트 · 프롬프트 본문 · 평가 데이터 · 데모 콘텐츠 |

- 플랫폼 견본(카탈로그)은 없다(09-26). 노드의 출력 모양은 워크플로우의 `output.example`이 정한다. 준수율 평가 기준 스키마는 `demo/brand/eval_schemas/`(서비스 규격 아님).
- 경계에 걸치는 변경(예: 프롬프트가 출력 스키마를 바꿈)은 상대 트랙에 통보한 뒤 병합한다.

## 2. 코드가 어디 있나 (현재 구현 위치 — 바뀌면 이 절을 고친다)

| 무엇 | 위치 | 비고 |
| --- | --- | --- |
| 실행 엔진 **실제 구현** | `spike/linear-mvp/` | `runtime/`은 설계된 구조(빈 폴더). 이동은 v2 |
| 템플릿 참고 구현 | `spike/linear-mvp/poc/` | README 참조. `step1_template.py`는 실행 금지(Claude 경로) |

| 프롬프트 초안 | `prompts/`, `spike/linear-mvp/prompts/` | 파일로 관리. 코드에 박지 않는다 |

백엔드 ↔ Runtime은 **202 + 폴링**, 에이전트 전개는 Runtime이 한다. 상세는 `docs/integration-guide.md`.

## 3. 설계 원칙 — 어기면 리뷰에서 되돌린다

1. **판정은 코드, 제안은 모델.** 스키마 검증 · 실패 책임 판정 · 분기 조건 평가 · 견적 · 정산에 LLM을 쓰지 않는다. 돈 계산의 근거는 결정적이어야 한다.
2. **프롬프트 원문은 어디에도 남기지 않는다** (SEC-001). 응답 · 로그 · 예외 · 임베딩 텍스트 어디에도. 마스킹은 단일 출구에서 한다.
3. **출력 모양의 원본은 판매자의 JSON 예시.** Runtime이 예시에서 구조화 출력 스키마를 만든다(`src/shape.py`). 플랫폼이 형식 목록을 따로 두지 않는다 — 수작업 이중 관리 금지.
4. **입력 형식은 없고, 출력은 판매자가 예시로 선언한다** (계약 v2.1 · 09-26). 노드는 앞 노드(들)의 결과 전체를 자동으로 받고, 출력은 `{kind:"text"}` 또는 `{kind:"json", example:{...}}`이다. 예시의 키 · 타입이 규격이고 `null` 값은 선택 항목이다. 견본 목록 · 연결 호환 판정을 다시 넣지 않는다. 분기는 상위 노드 출력 예시의 스칼라 필드만 참조한다(저장 시 코드 검사, 문자열은 대소문자 · 공백 무시). 봉투는 Runtime이 씌우고, LLM은 payload만 만든다.
5. **LLM은 GMS 경유 Gemini만** (`LLM_API_KEY` · `LLM_BASE_URL` · `LLM_MODEL`). 기본 모델은 **`gemini-2.5-pro`**(09-26, Flash에서 전환 — 크레딧 여유 · 분기 판정 안정). 워크플로우 `model` 필드로 Flash를 고를 수 있다. Claude 등 다른 경로는 쓰지 않는다. 개발 반복은 `--mock`. 모델을 바꾸면 `pricing.MODEL_PRICES` · `compose.yaml` · `.env.example` · 계약 §13을 함께 고친다.
6. **두 서비스는 stateless.** 이력 · 정산의 원본은 백엔드 DB. Runtime 상태는 메모리라 재시작하면 사라진다.
7. **결정 로직에는 테스트가 따라온다.** 검증 · 판정 · 분기 · 견적 코드를 바꾸는 MR은 그 경우의 테스트를 함께 낸다.
8. **스모크 직선(엑셀 → 분석 → 텍스트 → PDF)은 항상 돌아야 한다.** 기능을 붙이면 `--mock`으로 확인하고 MR "테스트 결과"에 적는다.
9. **Runtime은 돈을 모른다.** 토큰 · 모델 · 공시 단가 USD까지만 낸다. ABC · 노드 단가 · 청구액 · 환불액 · 환산율은 백엔드의 것이고 Runtime 코드 · 계약에 넣지 않는다. 판매자 테스트는 같은 `POST /v1/runs`에 `mode=test`다.

## 4. 비밀

- `.env` · `*.pem` · API 키 · 서비스 토큰 · GitLab 러너 토큰을 채팅 · 문서 · 커밋 · 로그에 쓰지 않는다. 출력에 섞여 나오면 요약에서 뺀다.
- **비밀 파일은 열지 않는다.** 키 이름만 필요하면 사용자에게 묻는다. `.claude/hooks/guard-secrets.mjs`가 `cat .env` · `grep -r KEY` 류를 막는다.
- 비밀은 EC2 환경변수 · GitLab CI/CD Variables로만 주입한다. `.env`는 커밋하지 않는다(루트 `.gitignore`가 막는다).
- 모델 가중치 · 학습 산출물은 커밋하지 않는다.

## 5. Git

- `develop-AI`에서 `feat/{내용}` 분기 → **작업(Task) 단위 커밋** → `develop-AI`로 MR. `master` · `develop-*`에 직접 push 금지.
- 커밋 메시지 `[S15P21A403-N] type: subject`. N은 브랜치의 스토리가 아니라 **실제 수행한 작업 번호**. `.githooks/commit-msg`가 검사한다.
- 커밋 · push · MR · 브랜치 삭제는 **사용자가 요청할 때만** 한다. push 전에 한 번 확인한다.
- 원격에 올린 브랜치는 rebase 하지 않는다. develop 따라잡기는 merge.

## 6. MR

- 타이틀 `[에픽 코드] 작업 타이틀`. 본문 템플릿은 GitLab이 자동 적용한다.
- **템플릿은 구조를 그대로 두고 값만 채운다.** 섹션 · 순서 · 안내 주석 · 체크박스 목록을 지우거나 바꾸지 않는다.
  - 해당 없는 **변경 유형은 체크만 하지 않은 채 그대로 남긴다.** 안 쓰는 줄을 지우지 않는다.
  - `<details>` 스크린샷 블록, `## 체크리스트`, `## 영향 범위 / 배포 시 주의사항`도 빠뜨리지 않는다. 템플릿 섹션은 **작업 내용 · 변경 유형 · 관련 이슈 · 테스트 결과 · 스크린샷/데모 · 리뷰 포인트 · 영향 범위 · 체크리스트 여덟 개**다.
  - 체크리스트는 **사실인 것만** 체크한다(빌드 · 테스트 통과 등 확인한 것). 셀프 코드 리뷰처럼 사람이 판단할 항목은 비워 두고 사용자가 표시한다.
  - 에이전트가 MR 본문 초안을 줄 때도 **템플릿 전문을 채운 형태**로 준다. 일부 섹션만 발췌하지 않는다.
- **MR 본문을 `git push -o merge_request.description`으로 채우지 않는다.** push 옵션에는 개행이 들어가지 않아(`push options must not have new line characters`) 헤딩 · 체크박스가 전부 깨진다. 템플릿이 자동으로 붙게 두고, 본문은 GitLab 웹에서 채운다. push 옵션은 `merge_request.create` · `target` · `title`까지만 쓴다.
- **작업 내용은 불릿 3개 이하, 각 한 줄, "무엇을"만.** 설계 이유 · 수식 · 배경은 본문에 풀지 않고 문서 링크나 리뷰 포인트로 넘긴다. 길어지면 `<details>`.
- **본문에 전체 티켓 키를 쓰지 않는다.** Jira가 본문을 스캔해 MR을 연결하고, 병합 시 자동화가 그 티켓을 완료 처리한다. 설명에는 번호만(`235`). 전체 키는 **"관련 이슈" 섹션에만**, 그것도 이 MR이 실제로 닫을 티켓만. (`git-workflow.md` §4.3은 "포함된 커밋의 이슈 전부"라 하지만 AI 파트는 자동화 때문에 이렇게 좁힌다.)
- `[SYNC]` · `[DEPLOY]` MR은 템플릿을 채우지 않는다. 타이틀 + 한 줄 (`git-workflow.md` §5).

## 7. Jira

- 커밋의 티켓 키 → MR 병합 시 **자동 완료**. 매일 23:30 마감 지난 티켓도 자동 완료. 보드는 실제보다 앞서 보인다.
- 티켓 상태 · 스토리포인트 · 우선순위 · 마감일은 사용자가 명시하지 않으면 바꾸지 않는다. 제목 · 설명 수정은 먼저 묻는다.
- 티켓 생성은 사용자가 한다. 에이전트는 내용(제목 · 설명 · 근거)만 만든다.

## 8. CI

- `.gitlab/ci/ai.gitlab-ci.yml`을 고치면 push 전에 파서로 검증한다. `.claude/hooks/validate-ci-yaml.mjs`가 저장 직후 자동으로 돌린다. 수동: `uv run --no-project --with pyyaml python -c "import yaml;yaml.safe_load(open('.gitlab/ci/ai.gitlab-ci.yml',encoding='utf-8'))"`
- 스크립트 줄에 `콜론+공백`(예: `'size: {{…}}'`)이 들어가면 YAML이 키로 읽어 파이프라인이 "yaml invalid"로 죽는다. 그런 줄은 `- |` 블록 스칼라로 감싼다.
- 잡 순서 `ai:build` → `ai:test`(mock 스모크, LLM 호출 없음) → `ai:deploy`(수동). MR 파이프라인은 LLM을 호출하지 않는다.

## 9. 서버

- EC2 읽기 전용(health · `docker ps` · 로그)은 그냥 한다. 컨테이너 기동 · 중단 · 설정 변경 · 패키지 설치는 **먼저 묻는다.**
- `ubuntu`는 docker 그룹이 아니다 — `sudo docker`.
- `develop-AI` 배포와 `master` 배포는 같은 컨테이너를 덮어쓴다.

## 10. 문서

- `docs/`는 배포용 규격 · 명세만. 고치면 버전 · 날짜를 올리고 영향받는 파트에 통지한다.
- 설계 이유 · 로드맵 · 인수인계는 팀 문서 폴더(레포 밖)에 있다. 그쪽 문서는 담당자와 합의 후 갱신한다.
